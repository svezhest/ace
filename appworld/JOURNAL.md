## 2. Стартовый харнесс = апстрим

Апстрим: `~/Projects/appworld/repo`, HEAD `42b5bcf`. Агент `simplified_react_code_agent`
(`experiments/code/simplified/{react_code_agent,agent,language_model}.py`). Конфиг — шаблон
`experiments/configs/_generator/templates/simplified_react_code_agent.jsonnet.j2` в том виде, в каком он уже
запускался на этой модели (`experiments/configs/ornith9b_react_dev.jsonnet`, базовый прогон dev от 17.10):
- промпт `react_code_agent/instructions.txt` (sha256 `c41f7852…534b`) = `src/starting_prompt.md` байт в байт;
- T=0, seed 100, без max_tokens, без tools; `ignore_multiple_calls: true`, `max_prompt_length`/`max_output_length: null`,
  `max_steps: 50`;
- `appworld_config`: random_seed 100, raise_on_extra_parameters.

Что перенесено в `harness.py` как есть:
- `.lstrip()` шаблона, рендер Jinja2, `+ "\n\n"`, разбиение по маркерам `USER:\n` / `ASSISTANT:\n` / `SYSTEM:\n`;
- извлечение кода: первый полный блок ```` ```python ````, ответ обрезается после него; незакрытый блок в конце закрывается;
  ответ без кода → исполняется пустая строка (AppWorld отвечает «No code available to execute.»);
- в беседу идёт обрезанный ответ + `"\n\n"`;
- вывод: `"Output:\n```\n" + вывод + ("\n" если нет) + "```\n\n"` user-сообщением;
- 50 ходов, после каждого исполнения проверка `task_completed`.

Известные баги демо оставлены (метод должен найти их сам): пароль берётся как
`[... == "spotify" for ...][0]["password"]` (список bool), `spotify_access_token` нигде не присвоен, пагинация `while page_index < 10`.

  в конфиге они выключены.

## 3. Мост, слоты и чёрный ящик

Бенчмарк — отдельный процесс на эпизод: `runner/env_server.py` в venv AppWorld, HTTP на свободном порту 127.0.0.1.
Он делает для одной задачи ровно то, что `appworld run` + `appworld evaluate`:
- `AppWorld.initializer(update_defaults=True, experiment_name, random_seed=100, raise_on_extra_parameters=True)`,
  `AppWorld(task_id)`, `set_random_seed(100)`;
- `/fill` — рендер шаблона с параметрами агента;
- `/execute` — `world.batch_execute([code])[0]`;
- `/completed` — `task_completed()`;
- `/finish` (зовёт только runner, после эпизода) — `world.close()`, затем `evaluate_task` с очисткой кэша БД, как
  в `evaluate_tasks`.

Runner сам поднимает процесс на эпизод и гасит его после `/finish` (ждёт выхода, иначе kill своего PID).
Выходы AppWorld лежат в `runs/<tag>/appworld/experiments/outputs/run_N/`. `APPWORLD_ROOT` = эта папка с симлинком
`data` → `~/Projects/appworld/data`.

`view/src/bridge.py` — только транспорт, 42 строки на urllib: `fill(text)`, `execute(code)`, `done`, `STEP_LIMIT = 50`.
Ни id задачи, ни путей, ни кода AppWorld в src нет; харнесс работает в своём venv без пакета `appworld`.
Docstring моста — спека: что делает каждый вызов и какие слоты есть.

### Слоты шаблона

Как оформлено:
- В `starting_prompt.md` слоты стоят как в апстриме: `{{ main_user.first_name }}`, `{{ main_user.last_name }}`,
  `{{ main_user.email }}`, `{{ main_user.phone_number }}`, `{{ app_descriptions }}`, `{{ instruction }}`.
- Харнесс отдаёт весь текст промпта в `episode.fill(text)`; заполняет мост, то есть процесс бенчмарка. Значения
  (поля задачи, объект supervisor, сборка JSON описаний приложений) живут только в `env_server.py`, вне вида.
- Модель узнаёт про слоты из двух мест:
  - `README.md`, строка про `starting_prompt.md`: «`{{ ... }}` in it are slots that the benchmark fills with the
    task's values (list in `bridge.py`); the slot names are fixed»;
  - docstring `bridge.py`: `fill(text)` рендерит текст как шаблон Jinja2; дан список переменных с одной строкой смысла
    на каждую; значения харнессу доступны только через `fill()`.

Почему так:
- **«Нельзя менять» сказано как устройство, а не запрет.** Значений в src нет, набор имён фиксирован бенчмарком.
  Модель может переставить или убрать слот в своём промпте: это правка харнесса. Подменить значение или завести
  новую переменную она не может: неизвестное имя Jinja2 отрисует пустой строкой.
- **Jinja2 назван прямо.** Это стандартная форма, её семантику модель знает (`{% %}`, неизвестные имена, удаление
  одного завершающего перевода строки). Про устройство AppWorld это ничего не говорит. Без этого поведение `fill` на
  правленном тексте было бы загадкой.
- **Значения слотов видны в логах.** Это нормально: модель-исполнитель их и видела. В src их нет.

Утечек нет (тест `test_message_shapes_and_no_leaks`): в беседе нет id задачи, «ground_truth», «experiment»,
«evaluation», «test_», не осталось ни одного `{{`. Каждое сообщение — часть промпта, ответ модели или
`Output:`-сообщение с выводом среды; ключи сообщений ровно `{role, content}`.

Харнессу доверяют так же, как в ALFWorld. Технически код в src может сам постучаться в порт бенчмарка и вызвать
`/finish`. Защиты нет: правки метода надо смотреть глазами. `/finish` закрывает мир, после него `/execute` отвечает
ошибкой.

### Причины в `results.jsonl`

Уровень подсказок 0: `{run, ok, reason}`, где reason:
- `success` — оценка AppWorld прошла;
- `wrong result` — `complete_task` вызван, оценка не прошла (сюда же `status="fail"`);
- `step limit` — 50 ходов без `complete_task`;
- `context exhausted` — 400 по контексту.

Технические причины: `timeout` (вызов дольше 600 с или эпизод дольше 3600 с), `model error`, `harness error`,
`harness stopped early`, `runner error`.

Проваленные проверки AppWorld в results не попадают. Они лежат только в приватной `meta.jsonl` (поле `evaluation`).
`--hint-level 1` добавит «K of N checks passed», `2` — ещё тексты проваленных требований. Это заготовка для абляции:
уровни решает автор, по умолчанию 0.

## 4. Squeeze-прокси на 8089

Что на самом деле слушает 8089:
- pid 82016, `python scratchpad/cap_proxy.py scratchpad/cap_proxy.log`, запущен 21.10.
- Файла `cap_proxy.py` на диске уже нет. Его текст восстановлен из транскрипта сессии 19.10: прокси импортирует
  HTTP-обработчик из `~/Projects/appworld/squeeze_proxy.py`, но вместо `Squeezer` подставляет `Cap`. `Cap` только
  дописывает `max_tokens=4000`, если в запросе его нет. Сообщения не трогает.
- Проверка по его логу: **71 673 запроса, у всех `chars_before == chars_after`.** Сжатия на 8089 нет и не было. Агент
  ALFWorld видел имя `squeeze_proxy` в трейсбеке и сделал вывод о сжатии.
- Процессов `squeeze_proxy.py` и `tree_proxy.py` сейчас нет.

Почему AppWorld через 8089 не идёт: апстрим не шлёт max_tokens, а `Cap` добавил бы 4000 — это уже отклонение.

Решение: **исполнитель AppWorld ходит прямо в шлюз `http://127.0.0.1:8090/v1`**, как в апстримном конфиге
`ornith9b_react_dev`. Прокладок нет вовсе.
- Перед стартом `run.py` проверяет через `lsof`, что порт URL слушает сам `qwen-gateway`, и пишет это в `run.json`.
  Иначе не стартует.
- Шлюз — pid 43258, `GATEWAY_THINKING=off`, `GATEWAY_DEFAULT_MAX_TOKENS` не задан (= до конца контекста).
- Подмена промпта `tree_proxy.py` не используется.
- Воркер, шлюз, порты 50051/8090/8120 и прокси 8089 не трогал и не перезапускал. ALFWorld продолжает ходить через
  8089; на ALFWorld `Cap` не влияет, там `max_tokens=4096` задан.

## 11. Открытые вопросы
