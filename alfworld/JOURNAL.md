## 2. Выбор бейзлайна

Взят стартовый харнесс Harness-R1 (2608.02276), их строка «без патча» (Qwen3.5-9B: 40.6%, 203/500).
Источники: `ref/Harness-R1/code/life-harness/AgentBench/src/server/tasks/alfworld/task.py` (цикл `alfworld_run`,
`get_task_instruction`), `configs/tasks/alfworld.yaml` (инструмент `take_action`, `max_step: 50`),
`reproduction/alfworld_e0/data/evaluation_settings.json` (T=0, max_tokens 4096, thinking off, tool_choice auto,
50 шагов), `client/agents/http_agent.py` (клиент модели).

Почему этот вариант:
- Harness-R1 — единственный конкурент с 9B-исполнителем на ALFWorld, и у него выложены сплит и трассы. Сравнение
  будет прямым.
- Остальные варианты дальше. SkillOpt: Qwen3.5-4B, тест valid_unseen 134, свой промпт с навыком. HarnessEvo: 7B,
  ReAct, до 40 шагов, кода нет. Life-Harness: та же подложка AgentBench, 4B.
- Классический ReAct-промпт с демо (Reflexion/ExpeL) у Harness-R1 не используется.

Что совпадает с Harness-R1 дословно:
- системный промпт, включая опечатку «complete)» и « Reminder:»;
- инструмент `take_action` (схема и описание «Take an action.»);
- первое сообщение `"Here is your task. " + наблюдение + " AVAILABLE ACTIONS: " + действия через \n + "\n"`; так же
  оформлен каждый ответ среды (роль `tool`);
- сообщения харнесса при отсутствии вызова инструмента и при битых аргументах;
- парсер действия: первая строка, lower, иначе ближайшее допустимое по BLEU (`process_action`);
- срез «You arrive at loc N. »;
- 50 ходов модели, каждый ход считается, включая ходы без вызова инструмента;
- провал при трёх одинаковых сырых действиях подряд (после ≥4 шагов), проверка идёт до проверки победы;
- успех — флаг `won` игры;
- T=0, max_tokens 4096, без penalty;
- клиент: 3 попытки, ошибка контекста завершает эпизод, вызов инструмента, написанный текстом, достаётся из
  `content` (транспортный шим их клиента).

Подложку Life-Harness (H2–H5) Harness-R1 при оценке выключает: все флаги `store_true` по умолчанию выключены.
Без патча это голый цикл; он и есть наш старт.

### Демо

В разборе (`2608.02276-HarnessR1-prompts.md`, §5) написано «+ одно демо по типу задачи из
`alfworld_multiturn_plan_first.json`». По коду это не так: `get_prompt` в `alfworld_run` не вызывается. Пример
трассы в их пакете начинается сразу с «Here is your task.». Демо в наш старт не включены.

### Хуки

Имена и контракты возврата взяты у Harness-R1 как есть: `on_init` → skills/tool_hint, `make_pre_hint` → message,
`on_before_action` → block_and_prompt / rewrite_action / force_action, `on_post_step` → inject_hint / force_action.
Точки вызова и порядок те же, что в `task.py`:
- skills идут в системный промпт под «Some tips that may help for this task:»;
- сообщение блока или переписывания вставляется user-сообщением;
- force_action из `on_post_step` подменяет следующее действие;
- упавший хук = None.

Отличия от Harness-R1:
- В `ctx` только то, что видел агент: observation, admissible, output, action{raw, normalized, final_action,
  in_admissible}, step, max_step, remaining_steps, history{last_actions, last_observations}.
- Рукописных полей Life-Harness (`task.*` из разбора задачи, `world.*`, `state.*`, `predicates.*`) нет: это
  рукописная подложка (см. разбор, «Не брать»).
- Нет AST-песочницы и лимитов их `compile_hook`: хуки — обычный модуль `hooks.py`.
- `tool_hint` действует на эпизод. У них он менял `self.tools` задачи и оставался на следующие эпизоды воркера.

## 4. src/ и тесты

- `bridge.py` — `Episode`:
  - `reset()` возвращает первое сообщение;
  - `match(raw)` — парсер бенча;
  - `step(action, raw)` возвращает текст ответа среды и правило трёх повторов;
  - `observation`, `admissible`, `done`, `won`;
  - `hint(level)`: 1 — длина плана эксперта (планировщик fast-downward через `policy_commands`), 2 — сам план.
    Только для абляции, по умолчанию 0.
  - `STEP_LIMIT = 50`.
  - Ничего об игре (путь, тип задачи, план) в беседу не попадает; это проверяет тест.
- `harness.py` — цикл `run(episode, llm)`, собирает беседу из `src/*.md` и текста моста; четыре точки хуков.
- Вне src (`runner/`):
  - бюджет: 50 вызовов модели (51-й → «step limit»), 3600 с на эпизод («timeout»), 400 по контексту →
    «context exhausted», 3 неудачные попытки → «model error», исключение в коде харнесса → «harness error»;
  - запись логов;
  - проверка, что беседа только дописывается (`append_only` в meta).
  - Причины в `results.jsonl`: success / step limit / repeated action / context exhausted / timeout / model error /
    harness error / harness stopped early.
- Логи:
  - `logs/run_N.jsonl` — по сообщению на строку: role/content, tool_calls у ассистента, tool_call_id у tool. Ровно
    список сообщений харнесса: всё, что ушло в модель и пришло из неё, плюс последний ответ среды.
  - `logs/results.jsonl` — `{run, ok, reason}`; при `--hint-level ≥1` добавляется `hint`.
  - Прогон идёт из снимка `runs/<tag>/src`, и `view/logs` заменяется только при совпадении хэша src.
- Тесты (`tests/test_harness.py`, 10/10 зелёные):
  - экспертные действия дают success;
  - форма сообщений: каждое сообщение — либо ответ модели, либо промпт из src, либо текст моста в формате
    бейзлайна; путь игры, «tw-pddl», «policy», «expert», «pick_» в беседе не встречаются;
  - три повтора → repeated action на 4-м ходу;
  - 50 ходов → step limit;
  - хуки, возвращающие None (и портящие копию ctx), дают побайтно ту же беседу, что без хуков;
  - эффекты хуков (skills, pre_hint, block) доходят до беседы, упавший хук игнорируется;
  - `run.py` на заглушке пишет `run_N.jsonl` и `results.jsonl` с ключами ровно {run, ok, reason}, в src не
    появляется `__pycache__`;
  - уровни подсказок 1 и 2.

### Цена

- Эпизод ≈ 4 мин модели в среднем при 4 потоках. Провал на лимите — 7–8.5 мин, успех — 1–5 мин.
- **Прогноз замера на 40 задачах при 4 потоках: ≈ 40 мин**, если успехов около 75%, как в smoke.
  - При доле успеха ~40%, как у Harness-R1, средний эпизод ≈ 340 с, и замер займёт ≈ 1 ч.
  - Плюс хвост последних эпизодов, до ~8 мин.
- Для сравнения, AppWorld: эпизод — медиана 5.5 мин, 90 задач — 12.4 ч модели.
- Больше потоков (8–16) не проверял: задержка вызова при 4 потоках уже 6.4 с против ~4 с при одном.
