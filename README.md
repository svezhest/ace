# NRHSI — самоулучшение харнесса LLM-агента силами самой модели

Харнесс — всё, что окружает модель, кроме весов: промпты, код цикла агента, хуки. Здесь малая модель
(Ornith-1.5-9B) сама улучшает свой харнесс, без более сильного учителя: читает свои проваленные прогоны,
правит код и промпты, новый вариант замеряется на свежих задачах.

Малая модель часто предлагает плохие правки. Жадный поиск (как в Self-Harness: принятая правка сразу становится
основой, решение по 2 попыткам) такие правки закрепляет. Здесь вместо этого дерево: хороший вариант остаётся
точкой роста, плохой ребёнок его не сдвигает — берётся следующая правка из пула того же узла.

Своего замера прироста у метода нет. Деревья 31.10–2.11 дали прирост на train ALF, на val он не подтвердился. С 3.11
метод отлаживается по компонентам: писатель, оценщик правки внутри его цикла, ревьювер. Цель с 19.11: 9B с мышлением
(T) в каждой роли догоняет 27B без мышления (NT). Где мы по каждой теме и насколько это твёрдо — [docs/MAP.md](docs/MAP.md),
задачи — [docs/TASKS.md](docs/TASKS.md).

## Цикл

```
узел (src/) ── замер: M свежих случайных задач ──> доля ok + логи прогонов
   │
   └─ ревьювер: по сессии на проваленный прогон (шаги прогона в первом сообщении) -> report (наблюдения)
        └─ писатель: наблюдение -> edit(path, old, new) по копии src/
             └─ finish -> оценщик: Ok / Failed с местом поломки; Failed — писателю, правит дальше
                  └─ кандидат в пул узла
                                                                     │
следующий узел = замер кандидата из пула узла с лучшей долей ok  <───┘
```

Ревьювер (в коде и старых журналах — исследователь, `nrhsi/researcher/`) и писатель (редактор, `nrhsi/editor/`) —
одна и та же модель в роли coding-агента: bash только на чтение, свои инструменты (`report` / `edit`), `finish`.
Оценщик — отдельные вызовы модели без инструментов: логика правки (блок на каждый задетый прогон, перепрогон после
промпта) и промпт (всё, что модель получает до шага 1, до и после правки: цель вместо запрета, без деталей задачи).
Вердикт оценщика писатель получает как есть, вместо механического «Ok» после smoke.

## Запуск

Нужны macOS (`sandbox-exec`, python3 из Command Line Tools), модель за OpenAI-совместимым API (адрес и генерация —
из `stands/<имя>.json`, `--stand`), ALFWorld (`alfworld/.venv`, игры в `ALFWORLD_DATA`, по умолчанию
`alfworld/data/alfworld`) и/или AppWorld (`appworld/.venv`; репозиторий AppWorld с данными и
venv — `APPWORLD_DIR`, по умолчанию `~/Projects/appworld`).

```
cd alfworld && .venv/bin/python runner/run.py --view view_v3 --n 40 --seed 1 --tag base   # замер -> runs/base, логи в view_v3/logs
python3 -m nrhsi.researcher --home H --view V --runs 11 --policy final --stand res9t --seed 1 --tag r11   # ревьювер на run 11
python3 -m nrhsi.editor --home editor --bench alf --input-text obs.md --stand res9t --seed 1 --tag e1   # писатель + оценщик -> editor/out/e1.diff
python3 -m nrhsi.tree alfworld --out runs/tree1 --m 40 --k 5 --s 3 --children 10 --lint editor/lint
```

`--runs` с одним прогоном — сессия по этому прогону: первое сообщение — постановка и вывод `runs steps N`. Без
`--runs` — K случайных провалов (`--k`, `--seed`). Писатель на каждый finish с изменённым `src/` отдаёт правку
оценщику; оценщик читает то же наблюдение, что писатель, файлом — поэтому вход писателя `--input-text`. Вход
`--input` (report сессий ревьювера по тегу) с оценщиком пока не связан. Тесты бенчей: `cd alfworld && .venv/bin/python -m pytest -q tests` (и так же в `appworld`).

По ключу из 11 провалов с вкладом харнесса верно названы: 9B T — 5 и 5 (seed 1 / 2), 27B NT — 7; добавки к первому сообщению (src/, ближайший пройденный прогон) 9B не подняли ([RV2](docs/lab/1124/RV2-per-run-steps.md)). ## Модели на стенде

Профили — `stands/<имя>.json`: модель, шлюз, генерация. Профиль пишется в мету каждого прогона (`run.json`: `stand`) и
каждой сессии (`provenance`). Основные:

| профиль | модель | генерация | где |
|---|---|---|---|
| `res9t` | Ornith-1.5-9B, MLX 8 бит (`stand9q.sh`) | мышление, бюджет 2048, T 1.0, top_p 0.95, top_k 20 | ревьювер 9B T |
| `eval9tc` | то же | мышление, бюджет 16384, T 1.0 | оценщик 9B T |
| `res27`, `plain27` | Qwen3.8-27B oQ4e (`stand27c.sh`) | без мышления, T 0 | ревьювер и оценщик 27B NT |
| `think27` | то же | мышление, бюджет 4096, T 0 | 27B T |

Исполнитель в бенчмарках — T = 0 (AppWorld: seed 100, без `max_tokens`; ALFWorld: `max_tokens` 4096). Кто сейчас
занимает видеокарту и как её взять и отдать — [docs/gpu.md](docs/gpu.md).
