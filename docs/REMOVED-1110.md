## Не тронуто

Это не мусор проб, а открытые изъяны базы. Чистка их не меняла, чтобы база осталась байт-в-байт.

- **Два ядра повтора — сведено к одному** (после чистки, шаг 1 тикета `docs/TICKET-1110-writer.md`). Было: авто-проверка
  через `tests/rerun_core.py` копии (`editor/rerun_writer.py`), проверка по тикету — через `editor/rerun.py` под Python
  харнесса (3.14). Файлы расходились только добавкой `--watch` / `__shape__` в `rerun.py` и языком строк `help=`; логика
  повтора была одинаковой. Стало: `rerun_writer.py` удалён, копия писателя собирается из `editor/rerun.py`, проверка
  по тикету идёт под `python3` песочницы (3.9.6). Что изменилось для модели: `tests/rerun_core.py` в копии длиннее
  на 1567 байт (в нём виден `--watch`). Сверка проигрышем: 42 сессии, отличаются только ответы bash на команды, читающие
  этот файл (100 ответов), и счётчик `truncated` в двух сессиях; ответ проверки по тикету на 77 копиях совпал.
- **Число в обрезке вывода rerun.** Вывод сначала режется до 8000 знаков, потом до 2500; во второй приписке
  «[... N characters in all]» N — длина уже обрезанного текста, а не полного.
- **Заголовок входа `--input`.** «references to logs/ point to the runs, which are not in this copy» — с `logs/` в копии
  это неверно. Входы `--input-text` несут свой заголовок.
- **Три добавки к тикету** (факт покрытия, значения операндов, перекрытый `def`) остались в базе без измеренного
  прироста по вердиктам: на них шли все пробы G3–G9, и автор велел чинить значения для `all/any` (c2e612a).
- **Ревьювер** (`nrhsi/researcher`) и ветки git (`feature/thin-writer`, `feature/verifier-r2`) не разбирались.
- **Неотслеживаемые файлы** `editor/logs_*.out` (около 100, прогоны 29–30.10) лежат на диске как были.
