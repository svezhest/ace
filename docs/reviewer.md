# Ревьювер (исследователь)

[Карта](MAP.md) · задачи — [TASKS](TASKS.md)

## Где мы

Ревьювер читает K проваленных прогонов и `src/` и пишет report — наблюдения для писателя (`nrhsi/researcher/`). В
журналах 28–31.10 он «исследователь». Калибровка шла 28.10–3.11 и остановилась, когда работа ушла к писателю. С тех
пор ревьювер не менялся. Его настоящие отчёты как вход писателя автор 11.11 отложил: «ревьювер не отточен». Что он
находит, мы знаем приблизительно. Точность report по ключу ответов низкая, и самые удачные сессии отличаются тем, что
утверждение проверено счётом или исполнением кода.

## Что известно и насколько твёрдо

- **Узкие вопросы с проверкой кодом работают, свободный поиск — плохо.** До NRHSI (23–28.10): «набрать и просеять» —
  все варианты плохи и неразличимы, 0,1–0,2 полезной находки на вызов, мусора 40–60 %; «просит ли задача ответа» — 69 из
  75, цитата сегмента — 0 выдумок из 33. Метки ставил один разметчик ([prehistory.md](prehistory.md)).
- **Удачу решает, проверено ли утверждение** счётом по событиям нужного источника или исполнением кода харнесса
  ([IDEAS-1031](IDEAS-1031.md)). Аудит подачи 31.10: демо AppWorld неотличимо от эпизода, писатель не видел ни одного
  настоящего ответа среды; утечек эталона нет ([AUDIT-1031](AUDIT-1031.md)).
- **Находка, привязанная к проверке** (`EVIDENCE_MODE=check`): ALF верно 2 из 38; подход не продолжаем (решение
  автора) ([P5](lab/1103/P5-reviewer-check.md)).
- **Лестница дневника** (напоминания, отбивка, предотчёт): «отбивка меняет время report, но не точность»
  ([NIGHT-1101](NIGHT-1101.md) §1–2). Say у исследователя работал, 100–270 знаков перед вызовом; петля 275 из 296 — брак
  отказа ([разбор 12.11](lab/1112/TALK-channels-and-say.md), §3).
- **Отчёты 9B как входы писателя опасны.** Из пяти настоящих отчётов два верных, два «симптом верен, механизм выдуман»,
  один «менять нечего» ([ST3N](lab/1110/ST3N-new-inputs.md)). Отчёт о run 32 обрывает 3–14 удачных эпизодов
  ([KT](lab/1111/KT-killer-ticket-alf-run32.md)).
- **Параметры не обоснованы.** Лимит `BASH_LIMIT=40` подобран относительно перебранного. K в источниках расходится:
  дневник 29.10 — ALF K=5, App K=3; researcher/JOURNAL §6 — общий K=3, «отличие K=3 от K=5 — в пределах шума»; A7 и
  README — K=5. Какое K принято, источники прямо не говорят.
- **Проверяльщик report (R2)** — короткая сессия в чистом контексте опровергает одно утверждение. По критерию автора
  проходит только v3 b10; «проверяльщик в цикл не берём» ([verifier/JOURNAL](../verifier/JOURNAL.md)).

## Почему нет уверенности

Ключ ответов есть только по 4 замороженным видам ([eval/key/README](../eval/key/README.md)), разметка — одного
разметчика. Калибровка шла на старой базе ревьювера и до перепрогона. Как ревьювер ведёт себя на нынешних видах, не
мерили. Тюнинг на новых трассах, бывший в плане автора, потерян при пересборке плана 30.10 и не делался.
