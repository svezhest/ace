# AB — bash после ответа проверки: есть чем разобрать «Failed»

[Указатель проб](../INDEX.md) · хронология: [12.11](../days/1112.md) · повод: [CK](CK-check-keep-passed.md), [BL](BL-bash-limit-anchor.md), [FA](FA-failed-line-any.md)

- **Повод.** Первая правка у 27B NT приходит на 22–36-м вызове bash при любом лимите ([BL](BL-bash-limit-anchor.md)), то
  есть при лимите 25 ответ проверки «Failed: this edit changes run 8…» писатель получает, когда разобрать его уже нечем:
  в докатах [CK](CK-check-keep-passed.md) и [FA](FA-failed-line-any.md) после развилки остаётся один вызов bash. При
  этом различитель «законный повтор против цикла» в рабочей копии виден готовым инструментом:
  `python3 tests/runs.py steps 8 6-11` печатает «7 @43 page_index = 0 → Output: Execution failed. Traceback…» и
  «9 @49 page_index = 0 → Output: 17». В BL большой лимит мерился без ответа «Failed» по задетым удачным (проверка
  отвечала «Ok»), а CK и FA — без bash. Вместе эти две правки не стояли.
- **Что сделано.** Ветка `feature/asm-1112` (e22e308) = `feature/failed-line-any` + `feature/bash-unnamed` (лимит
  bash 60, шагов 100, лимит писателю не назван). Нового кода нет.
- **Гипотеза.** С bash после ответа «Failed» писатель посмотрит шаги задетого удачного прогона и выведет различитель,
  а не будет крутить одну ручку.
- **Мерка.** Докаты `runs/ck_1112/logs/t1_ck_r0.jsonl` с хода 27, три штуки (`probes/1112/ab_roll.sh`), до 30 ходов.
  База — плечо `fa` пробы FA (та же развилка, тот же ответ проверки, лимит 25). Считаю: в скольких докатах после
  «Failed» есть вызов bash по удачному прогону; в скольких итоговый `src/` меняет run 1 и не задевает удачные.
- **Ожидание (записано до запуска, 04:16 по `date`).** bash по задетому прогону — в 2–3 из 3 (в записанном продолжении
  последний вызов ушёл именно на run 8 и 20). Чисто — 2 из 3. Сомнение: в BL на run 32 писатель сделал 18 правок
  подряд без единого bash при 30 оставшихся. Не сбылось, если чистых не больше, чем в базе.
