# BL — лимит bash как якорь: не называть его писателю

[Указатель проб](../INDEX.md) · хронология: [12.11](../days/1112.md) · повод: [P27](../1111/P27-base-27b-plain.md)

- **Повод.** На ступени 27B NT (T=0,6) первая правка приходит на 23–25-м вызове bash из 25 в 7 сессиях из 7. В
  системном промпте стоит строка «bash can be called 25 times; after that 3 turns remain without bash: edits are still
  applied and checked after each one, and then the session ends», в ответе проверок — «(they use no bash calls)».
  Автор, 12.11: «ты случайно не печатаешь лимит до его наступления? в любом виде: промпт, счётчик… блин ну понятно же
  что это якорь и брать в первую очередь»; о пополнении бюджета: «бесконечный цикл, и очень долго локально. опасно.
  просто сделай лимит большим»; о формулировке без числа: «bash calls are limited это даже не надо проговаривать».
- **Что уже есть в журнале.** [W1L](../1104/W1L-bash-limit.md) и запись 6.11 «Бюджет bash: правила промпта или ритуал»:
  у 9B чтение насыщается на 25–30 вызовах, при L=100 первая правка на 27,5, лимит не исчерпан; кандидат «лимит ~50»
  записан и не снят. Те замеры шли с числом в промпте и на стенде без ответа проверки на правку (П2). Вариант «лимит
  не назван» в указателе не найден (поиск 12.11: «без числа», «не называть», «скрыть лимит»).
- **Гипотеза.** Число в промпте — якорь: писатель читает «до лимита» и правит на последних вызовах. Без упоминания
  лимита первая правка придёт тогда, когда прочитанного хватает, и после неё останется bash на обороты «правка →
  ответ проверки → посмотреть задетые прогоны → сузить».
- **Плечи (ветки от develop d01e440, рабочие деревья `~/Projects/nrhsi-wt/`).**
  - U60 — `feature/bash-unnamed` (1097447): `BASH_LIMIT=60`, `STEP_BUDGET=100`; строка о лимите убрана из промпта,
    «this uses no bash calls» и «(they use no bash calls)» убраны. Лимит остаётся предохранителем: сообщение о конце
    bash приходит, только если он достигнут.
  - P60 — `feature/bash-60` (1b64477): те же 60 и 100, строка в промпте прежняя, с числом 60. Нужно, чтобы отделить
    «не названо» от «просто больше».
  - База — уже снятые сессии [P27](../1111/P27-base-27b-plain.md) при 25: `runs/n27_1111/logs/{t1,k10}_plain27t_s1.jsonl`.
- **Мерка.** 27B NT, профиль `plain27t` (T=0,6), входы № 1 (t1) и run 32 (k10) — там NT проиграл T; по одной сессии на
  клетку, каждая читается. Считаю: номер вызова bash перед первой правкой; сколько вызовов bash после первой правки;
  сколько оборотов «правка → bash → правка»; итог по повтору (`probes/1111/table.py`) и по правке против входа.
- **Ожидание (записано до запуска, 01:36 по `date`).** U60: первая правка раньше 20-го вызова bash в обеих сессиях;
  P60: на 20–30-м. Не сбылось, если в U60 первая правка на 23-м и позже — тогда якорь не в названном числе, а чтение
  просто занимает столько. Про итог (сузит ли № 1, подействует ли на run 32) ожидания нет: это следующий вопрос.
- **Запуск.** `probes/1112/wt.sh bash-unnamed t1 plain27t`, `… k10 …`, затем `probes/1112/wt.sh bash-60 t1 plain27t`,
  `… k10 …`; результаты в `runs/bl_1112`.
