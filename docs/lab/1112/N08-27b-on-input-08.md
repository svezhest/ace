# N08 — 27B на входе 08: верхняя ступень там, где лежат сессии 9B

[Указатель проб](../INDEX.md) · повод: [каталог ошибок 9B](CAT-9b-writer-errors.md), [P27](../1111/P27-base-27b-plain.md)

- **Повод.** Автор, ночь на 12.11: «какие замеры 9б уже есть? у нас просто сраная гора замеров писателя на 9б».
  Каталог показал: на свежем стенде (с 10.11) у 9B в обеих ветках есть только вход 08 — 34 сессии без рассуждения и
  32 с ним (`runs/fk_1110`, партии G3–G9). 27B на входе 08 не шёл, поэтому пара «27B NT против 9B» на одном входе не
  читается. Дешевле поднять верхнюю ступень на 08, чем снимать 9B на семи новых входах.
- **Вопрос.** Что 27B без рассуждения делает на входе 08 и какие классы ошибок из каталога 9B у неё есть, а каких нет.
- **Коммит.** develop на момент запуска. Профили `plain27t` (27B NT, T=0,6) и `think27` (27B T, T=0). Виды
  `runs/typed_1111`, лимит bash 25, хвост 3 хода — как у партий G3 (9B NT) и G7 (9B T).
- **Чем стенд отличается от партий 9B (10.11).** Сводка перепрогона явными предложениями ([RL](../1111/RL-rerun-log-line.md),
  11.11); виды typed_1111 вместо typed_1110 (убраны мёртвая проверка, run 19, вход 02). Пары читать с этой оговоркой.
- **Мерка.** 27B NT — три сессии (seed 1–3), 27B T — одна. Каждая читается; итог по `probes/1111/table.py` и по правке
  против входа; классы ошибок — по каталогу (К1–К15).
- **Ожидание (записано до запуска, 00:45 по `date`).** 27B NT: Ok/Ok без мёртвого кода и без задетых удачных — не
  меньше чем в 2 из 3 (у 9B на 08: Ok/Ok 10 из 33, точных по журналу 1 из 10). Вызовов bash после конца бюджета и
  падений — 0 из 3. Не сбылось, если чистых 0–1 из 3: тогда порог на этом входе выше 27B NT.
- **Запуск.** `probes/1111/series.sh runs/n27_1111 plain27t 1 1 2 3 -- 08`, затем `probes/1111/stand27.sh` и
  `probes/1111/series.sh runs/n27_1111 think27 1 1 -- 08`.
