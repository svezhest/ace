    называл рабочими две проверки, включая мёртвую; в виде без мёртвой проверки осталась одна — текст сокращён;
  - № 3 — верная деталь, выдуманный механизм: «проверка сравнивает ответ целиком, а проза разная; надо сравнивать
    только код» — просит то, что уже сделано (control, run 1);

  - № 5 — обобщение с одного прогона: законный повтор в удачном run 8 записан в ту же беду, просьба «блокировать
    любой код из последних шагов» (control, runs 1, 4, 8, 9).
- **Прибор.** Как в DS1, кроме лимита: `DS_BASH_LIMIT=50` (в промпте — 50; бюджет вызовов 120; окно харнесса
  150 000). Вид `runs/typed_1111/app_r1c`. Запуск: `DS_BASH_LIMIT=50 probes/1111/ds/tk.sh N on|off ТЕГ`, восемь
  сессий разом: `t2_plain … t5_think`. В DS1 лимит был 25 — сравнение с тикетом № 1 этим смешано.
- **Мерка.** Глазами по каждой сессии: что правит (код или промпт) и чем условие; проигрыш итога на девяти
  прогонах; спорит ли с входом; замечен ли законный повтор.
- **Ожидание (до запуска, 04:00 по `date`).**
  - № 2: без рассуждения — правка только промпта; с рассуждением — промпт и, возможно, код вопреки «харнесс не
    виноват».

    чередование.
  - № 4: обе правят промпт (пример или указание про данные в другой сущности); код не трогают.
  - № 5: с рассуждением — заметит, что run 8 прошёл и повтор там законный, просьбу буквально не исполнит; без
    рассуждения — исполнит окно, заденет удачные 8 и 20; заметит ли по сводке — не знаю.
- **Запуск.** 04:00–04:06 по `date`, восемь сессий разом. Расход — 2,26 юаня (48,97 → 46,71).

- **Ожидание и что вышло.**
  - № 2: «без рассуждения — только промпт» — не сбылось (промпт и проверка в хуке); с рассуждением — сбылось.
  - № 3: «обе отвергнут выдуманный механизм» — с рассуждением да, на втором ходу; без рассуждения нет: в итоговом
    тексте сессии — «The repeat guard compared the whole reply text», как во входе.
  - № 4: обе правят только промпт — сбылось.
  - № 5: сбылось в обеих частях. Без рассуждения сводку с расхождением в удачных прогонах сессия привела как
    подтверждение («acts differently from… 10 in run 8»).
- **Что это значит.**
  1. **С рассуждением ни одна из пяти сессий не оставила задетыми удачные прогоны 8 и 20**, и четыре из пяти
     записали различитель: «прежний шаг упал — повтор законен» (№ 1 в промежуточной версии, № 3, № 5) или «тот же
     код с теми же выводами» (№ 2). Пятая (№ 4) о нём рассуждала и правила промпт.
  2. **Без рассуждения вход исполняется как написан.** Там, где он ведёт к широкой правке (№ 3, № 5), итог
     задевает удачные 3, 8, 20; где нет — пороги счёта, которые на этих девяти прогонах удачные не задевают.
     Слов «passed» или о законном повторе в ответах этих сессий нет ни разу.
  3. **Проверка по тикету на плохом тикете работает против писателя.** В № 5 она ответила Ok на правку, ломающую
     удачный run 8 (он записан в тикет как прогон беды), и до конца отвечала Failed («no effect in run 4», «in
     run 8») сессии, которая этот прогон сберегла.
  4. **После правки промпта проверка слепа к коду:** «the prompt differs from the log, so nothing after it can be
     compared». В № 2 код обеих сессий повтором не проверялся; одна сессия (№ 3 без рассуждения) откатила правку
     промпта, «so the replays stay comparable».
  5. **Пример в промпте из задачи прогона** — в обеих сессиях № 4: решение задачи run 1 вписано в промпт агента.
  6. **Лимит 50** исчерпала одна сессия из восьми (№ 3 без рассуждения, пик промпта 71 213 — в окно 9B не
     вошла бы); остальные взяли 19–35. Первая правка — после 11–29 вызовов.
- **Уверенность.** По одной сессии на клетку; ход читан по сводке, не целиком. Различие «с рассуждением / без»
  держится на пяти парах и одного знака в четырёх.
- **Не проверено.** Что правки дают агенту — исполнитель не запускался. В № 1 лимит 25, в остальных 50. Тот же
  набор на 9B не шёл. «Задет только текст сообщения» в run 3 сверено по тексту расхождения у № 3 с рассуждением;
  у № 5 — по тому же виду строки.
