# FL — строка Failed называет ложную часть условия

[Указатель проб](../INDEX.md) · хронология: [11.11](../days/1111.md) · повод: ступень 27B без рассуждения, вход 01

- **Повод.** Сессия `01_plain27_s1` (27B без рассуждения, develop ca9f523). Первая правка (ход 19, bash уже кончился):
  `if len(steps) >= 2 and code == steps[-2].code and steps[-1].output == steps[-2].output` — сравнены выводы двух разных
  шагов чередования, условие не истинно никогда. Строка Failed ответила: «your `if len(steps) >= 2 and code ==
  steps[-2].code and steps[-1].output == steps[-2].` … was never true (… `len(steps)` = 49, `code` = …,
  `steps[-2].code` = …, `steps[-1].output` = '2\n')». Условие обрезано на 80 знаках, операндов показано четыре из
  пяти: `steps[-2].output`, который и делает условие ложным, в строку не попал; какая часть ложна — не сказано.
  Писатель выбросил всю часть про вывод (ход 20: задеты удачные 8 и 20, keep Failed), затем вернул её (ход 21: снова
  без эффекта). Сессия кончилась правкой без действия.
- **Пробовали ли.** TKV (значения операндов в строке Failed — принимаются), 6.11 «ran N times and was never true».
  Какая часть условия ложна — не называли; предел в четыре операнда и обрезка на 80 знаках — с тех пор.
- **Изменение (одно).** Ветка `feature/failed-line-parts`, `nrhsi/editor/gate.py`: условие целиком (до 200 знаков);
  если оно — цепочка `and`, по каждой части сказано «was true» / «was false», у ложной — значения её операндов;
  операндов в прежней форме — до шести. Проигрыш этой же сессии на ветке: остальные 19 ходов совпали слово в слово.
  Новая строка: «… was never true. At its last run, before model call 51: `len(steps) >= 2` was true; `code ==
  steps[-2].code` was true; `steps[-1].output == steps[-2].output` was false (`steps[-1].output` = '2\n',
  `steps[-2].output` = '{\n "album_id": 2, …' (930 chars, 58 lines))».
- **Замер.** Развилка хода 20 той же сессии (`editor/fork.py --final --last`), стенд plain27, температура 0 — одна
  попытка; база — записанный ход 20 (часть про вывод выброшена целиком).
- **Ожидание (до запуска, 19:06 по `date`).** Один к одному: вместо выбрасывания части писатель исправит сравнение
  (вывод этого шага с выводом того же кода два шага назад — недоступен до исполнения; либо `steps[-1]` с `steps[-3]`).
  Не сбылось, если ход тот же, что в записи (условие `code == steps[-2].code` без различителя).
- **Не проверяется здесь.** 9B; условия с `or` и вложенными вызовами; сессия целиком.
- **Итог, 19:12 по `date`.** Не сбылось: ход тот же, что в записи. С новой строкой писатель так же выбросил часть про
  вывод целиком (`if len(steps) >= 2 and code == steps[-2].code:`), текста в ответе нет. Одна попытка, температура 0.
- **Что это значит.** Строка Failed теперь говорит правду полностью (какая часть ложна и оба значения), но на этой
  ступени ход она не меняет: без рассуждения писатель чинит «никогда не истинно» удалением ложной части, а не
  поиском верного сравнения. Изменение оставлено на ветке, в `develop` не влито: эффекта нет, а строка стала длиннее
  (вывод до 160 знаков на операнд).
- **Не проверено.** С рассуждением (27B T, где значения читаются); 9B; несколько попыток при температуре выше нуля.
