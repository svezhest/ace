# DS1 — писатель на DeepSeek по правдоподобному тикету 9B о run 1 (11.11)

[Указатель проб](../INDEX.md) · хронология: [11.11](../days/1111.md)

- **Откуда.** Слова автора, 11.11: «запусти дипсик с reasoning и без него в режиме писателя с одним из этих тикетов
  1-5. два запуска писателя. все взаимодействие пишется в логи»; модель — «deepseek-v4.1-flash-1017, она же
  deepseek-flash».
- **Вопрос.** Что делает сильная модель на месте писателя, когда вход — отчёт, какой мог бы написать нынешний
  ревьювер 9B: верный симптом и объяснение «сравнивает только с предыдущим шагом», которое ведёт к правке
  «сравнить и с `steps[-2]`». Эта правка задевает удачные прогоны 8 и 20 (сверено проигрышем наивной правки на
  копии вида: расходятся run 1, 4, 8, 9, 20). Прогоны различает вывод шага: в run 8 код сначала упал, после
  установки токена прошёл; в run 1 он каждый раз проходит с тем же выводом.
- **Пробовали ли.** На 9B — 89 сессий входа 01 в восьми ступенях полноты входа (разбор 11.11). Сильная модель на
  месте писателя на этом входе не запускалась. Проба 01m (5.11) — та же гипотеза о различителе, на 9B: 0 из 4.
- **Вход.** Тикет № 1 из пяти, написанных мной 11.11 в манере ревьювера (`runs/typed_1111/in/t1.txt`): самый
  вероятный «хороший» отчёт. Неточность вставлена нарочно: сообщения 61 и 67 названы побайтно одинаковыми, хотя
  проза в них разная. Тикет `docs/tickets_1111/t1.json`: control, run 1, keep нет — удачный прогон ревьювер 9B не
  называет.
- **Вид.** `runs/typed_1111/app_r1c` = `runs/typed_1110/app_r1` без мёртвой проверки «тот же вывод» и без функции
  `output_text`, которой пользовалась только она (след узлов e3–e8; автор, 11.11: «убрать»). Проверка повтора кода
  теперь в строках 95–99.
- **Прибор.** `probes/1111/ds/run_ds.py on|off` — харнесс писателя без изменений (25 bash, 3 хода после, проверки
  после правки), модель `deepseek-flash`, T 0.6; без рассуждения max_tokens 4096, с рассуждением 16384.
  Рассуждение прежних ходов возвращается провайдеру (его требование), в счёт окна харнесса не идёт. Python
  песочницы 3.9.6 (develop). Запуск: `probes/1111/ds/t1.sh off ds_plain`, `probes/1111/ds/t1.sh on ds_think`.
  Логи: `runs/ds_1111/logs/` (ходы, рассуждение, вызовы, ответы), `runs/ds_1111/raw/` (сырые запросы и ответы).
- **Мерка.** Глазами: итоговая правка против входа и против девяти прогонов (проигрыш); заметила ли модель
  удачные прогоны в сводке проверки; появился ли различитель по выводу шага; что сказано в рассуждении о входе.
- **Ожидание (до запуска, 03:48 по `date`).** Обе сессии первой правкой сделают условие над кодом (окно или
  `steps[-2]`). Сводка проверки покажет расхождение в удачных 8 и 20; обе это заметят и сузят. С рассуждением —
  различитель по выводу или по падению прошлого шага; без рассуждения — счёт повторов или два периода.
  Не сбылось, если: сессия сдаёт правку, задевающую удачные прогоны, или различитель по выводу не появляется и
  с рассуждением.
- **Запуск.** 03:48–03:53 по `date`, обе сессии разом. Расход — 0,21 юаня (остаток 49,18 → 48,97).

  **С рассуждением, по ходам.** Ход 6, до чтения логов: «Re-running identical code might be legit if the
  environment changed state in between». Ход 9: находит законный повтор в самом run 1 (шаг 10 повторяет шаг 7 после
  установки токена): «rerunning a block after fixing an undefined var is legit and produced a *different* output
  (NameError → 23)» и формулирует различитель: «distinguish by *output*: if a step's code was run before and
  produced a NameError/failure then rerunning is legit». Ход 10: скрипт по всем девяти логам — повторы кода и упал ли
  прежний шаг; ход 11: «run_4 and run_8 repeats are legit retries after a NameError». Первая применённая версия
  (ход 15): пропускать повтор шага, прежний вывод которого не был падением; run 1 расходится с вызова 16, но и
  удачный run 3 — с вызова 5. Ход 16: «This is a false positive that breaks a passing run»; ход 17 — разбор: в run 3
  изменился только текст прежнего сообщения; прежний текст возвращён, удачные прогоны перестают расходиться (ход 20).
  Ход 27, уже без bash: случай «прочитал — изменил — прочитал снова», которого в логах нет, сочтён важнее раннего
  срабатывания («The false positive could derail a good run… reducing false positives is more valuable»), условие
  заменено на «цикл прошёл дважды». Функция `failed()` осталась в коде без вызова.

  **Без рассуждения.** 21 вызов bash на чтение (README, `src/` целиком, `tests/smoke.py`, прогоны 1, 9, 19, 4, 13),
  затем три правки подряд. Удачных прогонов правка не задела: порог 3, а законный повтор в логах встречается
  дважды. Объяснения порога в тексте ответов нет.
- **Ожидание и что вышло.**
  - «Первая правка — условие над кодом» — без рассуждения да; с рассуждением нет: различитель по падению прежнего
    шага был в первой же версии.
  - «Сводка покажет расхождение в удачных 8 и 20, обе заметят и сузят» — не сбылось: прогоны 8 и 20 не задела ни
    одна версия ни одной сессии. С рассуждением задет run 3, замечено и исправлено за два хода.
  - «С рассуждением — различитель по выводу; без — счёт повторов» — сбылось; в итоговой правке с рассуждением
    различитель заменён на правило периода.
- **Что это значит.** Объяснение из входа («сравнивает только с предыдущим») ни одну из двух сессий к `steps[-2]`
  не привело. Сильная модель с рассуждением нашла то, что различает прогоны, из логов — раньше, чем проверка ей
  что-либо показала, и без keep в тикете.
- **Уверенность.** Низкая как счёт: по одной сессии на плечо. Как наблюдение хода — прочитано целиком.
- **Не проверено.** Другие четыре тикета; вид с мёртвой проверкой; тот же вход на 9B (вход новый, на 9B не шёл).
  Что правки дают агенту на живых прогонах — исполнитель не запускался. У сессии без рассуждения хода мысли нет:
  заметила ли она законный повтор, неизвестно.
- **Сходство с 9B по процессу.** Обе сессии начали с README, читали исходники `tests/` (`smoke.py`; с
  рассуждением — `rerun.py` и `rerun_core.py` целиком), израсходовали все 25 bash; с рассуждением сессия кончилась
  по лимиту с неприменённой последней правкой.
