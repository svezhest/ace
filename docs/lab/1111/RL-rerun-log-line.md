# RL — в сводке повтора строка «-»: что было в логе на месте расхождения

[Указатель проб](../INDEX.md) · хронология: [11.11](../days/1111.md) · повод: [N27](N27-base-27b-thinking.md)

- **Повод.** Две сессии 27B с рассуждением споткнулись об одно место сводки `tests/rerun.py` после правки. Сводка
  печатает только новое сообщение («+ user: …») и не показывает, что стояло в логе на этом месте:
  - t5, ход 11: «wait, run 3 had 0 re-runs in my analysis!» — в удачном run 3 новое сообщение заменило прежнее сообщение
    той же защиты (повтор прошлого шага, он и в логе не исполнялся), а в удачных 8 и 20 — ответ среды `Output: …`
    (повтор в логе исполнился и дал данные). В сводке эти три случая — одна строка. Итог сессии: «the model in the log
    recovered on its own» — неверное чтение.
  - t3 (докат), ходы 24–25: оба оставшихся хода без bash ушли на вопрос «почему расходится run 3» и на вызовы bash,
    которого уже нет (`python3 tests/rerun.py 3` показал бы обе строки).
- **Пробовали ли.** В указателе и днях строки «-» в сводке нет. Близкое: G2 (одна строка-факт в ответе проверки, 5 → 10
  из 10), 10.11 «какой вызов у какого прогона». В подробном выводе (`rerun.py N`) строка «-» есть с самого начала.
- **Изменение (одно).** Ветка `feature/rerun-log-line`, `editor/rerun.py`: в сводке перед «+» идут строки «-» — первое
  сообщение лога на месте расхождения, по строке на прогон (удачные первыми, не больше 5, по 110 знаков); если у всех
  прогонов группы оно одно — одна строка без номеров. Группировка прежняя. Форма — обычный diff.
- **Замер.** Развилка записанной сессии (`editor/fork.py --last`): тот же ход, ответ проверки с новой сводкой
  (`probes/1111/rl/mk.py`). Стенд think27, температура 0 — одна попытка на точку; база — записанный ход.
  Проверка прибора: развилка t5 без замены должна повторить записанный ход 11 слово в слово.
  - t3 (докат), ход 24 (хвост без bash). Записано: «I'm quite confused…», вызов bash, которого нет.
  - t5, ход 11. Записано: условие не тронуто, в сообщение дописан совет про неопределённое имя.
- **Ожидание (до запуска, 17:14 по `date`).**
  - t3, ход 24: назовёт расхождение run 3 заменой текста прежней защиты и bash не вызовет. Не сбылось, если снова
    пойдёт выяснять run 3.
  - t5, ход 11: один к двум, что условие сузит. Против: решение «blocking them costs one step each» принято до правки
    со знанием, что повтор законный, и проверка по тикету отвечает Ok по run 8. За: теперь видно значение — в логе
    повтор дал `Output: 17` и список будильников. Не сбылось в любом случае, если run 3 снова назван загадкой.
- **Не проверяется здесь.** 9B; виды ALF (там в группе до 15 прогонов — длина сводки); сессия целиком (развилка — один
  ход); задевает ли строка «-» прежние записанные сессии (проигрыш gold — до влития в develop).
- **Итог первой формы («-» / «+»), 17:46 по `date`.** Три развилки, `runs/n27_1111/rl/`, 17:14–17:45.
  - Прибор: развилка t5 без замены повторила записанный ход 11 слово в слово (текст и аргументы edit) — сравнение с
    записью законно.
  - t3, ход 24. Bash не вызван, ход потрачен на правку: возвращена исходная проверка «тот же код, что на прошлом шаге»
    с прежним текстом, новая («код уже исполнился успешно») поставлена второй. С такой правкой run 3 шёл бы как в логе.
    Но прочитано неверно: «my new check doesn't fire for a repeat of a *failed* step» — новая проверка там как раз
    сработала (строка «+» это показывает), изменился только текст. Ожидание сбылось по действию, не сбылось по чтению.
  - t5, ход 11. Условие не сужено (ожидал этого два к одному). В рассуждении (19,6 тыс. знаков) слов «Output», «17»,
    «alarm», «passed» нет ни разу: строки «-» не использованы. Десять раз повторено «the observation explicitly asks
    for this behavior». Run 3 загадкой не назван. Ход ушёл на bash (`sed` и `rerun.py 1`).
- **Что это значит.** Строка «-» в виде diff на 27B — полдела: там, где писатель и так искал причину (t3), она
  заменила два потерянных хода правкой, но причину он вывел неверно; там, где не искал (t5), она не прочитана. Diff
  требует самому вывести, что шаг теперь не исполняется. Автор (17:3x): «модель такая: и что? … ей нужно прямо сказать
  что да как»; про ярлык «only the harness's own message is reworded» — «what the hell does it mean».
- **Вторая форма: явные предложения.** `editor/rerun.py`, `report_plain`: сводка после правки называет событие
  словами — «In the log the harness ran the model's code and the model got the output: "17". Now the harness does not
  run this code. The model gets this message instead: "…"»; смена одного текста — «The harness does the same as in the
  log: in the log it also did not run this code. Only the text of its message is different. In the log: … Now: …».
  Удачные прогоны отдельным разделом и первыми; оценок нет. Событие определяется механически: сколько шагов задачи
  (execute / send) было в логе до этого вызова и сколько сделал харнесс, чьё сообщение стояло в логе (env / harness /
  model). Подробный вывод `rerun.py N` и блок «Check against the observation» не тронуты. Где такого события нет ни в
  одном прогоне (нет изменений, иной промпт, падение), сводка прежняя, слово в слово.
- **Ожидание по второй форме (до запуска, 17:49 по `date`).** Те же два хода, `probes/1111/rl/mk.py` подставляет сводку целиком.
  - t3, ход 24: в рассуждении run 3 назван так, как сказано в сводке (поведение то же, другой текст), без «doesn't
    fire»; bash не вызван. Не сбылось, если причина снова выведена неверно.
  - t5, ход 11: значения из сводки («17», будильники, «passed») в рассуждении появятся — это проверка, что строка
    прочитана; сузит ли условие — один к одному: блок «Check» по-прежнему отвечает Ok по run 8, и тикет просит
    блокировать. Не сбылось, если значений в рассуждении снова нет.
- **Итог второй формы, 18:12 по `date`.** Две развилки, 17:50–18:11 (`t3r.fork2`, `t5.fork2`).
  - t3, ход 24: сбылось. «So in the log, at model call 5, the harness did NOT run the code (it triggered the old repeat
    guard). And now the new harness also does not run it… only the message text differs». Неверного «doesn't fire» нет,
    bash не вызван; ход ушёл на уборку (лишняя константа), в конце рассуждения — свой вопрос, не блокирует ли правило
    законный повтор после смены состояния.
  - t5, ход 11: событие прочитано, решение прежнее. «Run 3: only the message text changed (the same block, just with
    the new wording)»; «Runs 8, 20 (passing runs): the harness now blocks a re-send that was previously executed — this
    is the intended behavior change (… in the log it recovered and succeeded, so it's likely to recover here too)».
    Самих значений («17») в рассуждении нет. Условие не сужено; дальше — bash и план «страховки» (конец эпизода после
    трёх блокировок подряд).
  - **Сравнение форм на этих двух ходах:** событие названо верно — 0 из 2 с «-»/«+» (t3 — неверная причина, t5 — не
    прочитано), 2 из 2 с явными предложениями. Решение на плохом тикете (t5) не изменила ни одна.
- **Третья проба: блок «Check against the observation» без «Ok» по удачному прогону.** Один ход, t5/11; к сводке второй
  формы добавлена замена блока (текст вписан руками в `t5.last3.txt`, кода в `gate.py` ещё нет): «The observation names
  runs 1, 4, 8 and 9. — Runs 1, 4 and 9 failed in the log. Now the harness acts differently in each of them. — Run 8
  passed in the log: the task was solved there. Now the harness acts differently in it too: at model call 10 it does
  not run the code that it ran in the log.» База для сравнения — `t5.fork2`.
  **Ожидание (18:12 по `date`):** один к двум, что условие сузит: тикет прямо просит блокировать и приводит run 8 примером;
  по мерке «точность реализации входа» буквальное исполнение — не ошибка писателя. Смотрю прежде всего, что он скажет
  о run 8 в рассуждении и в итоге: исчезнет ли «it recovered».
- **Итог третьей пробы, 18:18 по `date`** (`t5.fork3`, 18:12–18:17). Условие не сужено (ожидал один к двум). Но чтение стало
  верным: «In the log, that re-run produced "17" (the number of songs). Now the model gets a "stop repeating" message
  instead»; «Hmm, this is a real concern: the model legitimately needs to re-run the same code after fixing the
  environment». Слова «recovered» больше нет (в `t5.fork2` было). Решение: «the observation explicitly asks for this…
  The observation is the spec here» — и косметическая правка. То есть с явной сводкой и блоком-фактом писатель видит
  вред и называет его, а исполняет тикет. По мерке «точность реализации входа» это не ошибка писателя: плохой тикет
  должен ловиться не здесь.
- **Вывод по 27B (пять развилок, по одной попытке на точку).** Явные предложения чинят чтение (верно названо событие:
  0 из 2 → 2 из 2; ложное «recovered» ушло после блока-факта). Решение на плохом тикете не меняет ни одна форма.
- **Проба на 9B: тот же ход после правки, прежняя сводка против явной.** Шесть записанных сессий 9B по входу 08

  вариант — в нём сводка заменена явной (`probes/1111/rl/mk.py`). Блок «Check» в обоих плечах прежний.
  Вид — typed_1110 (на нём записаны сессии), код сводки — ветка.
  **Мерки:** (1) доля ответов с вызовом bash, которого в хвосте нет; (2) доля ответов с правкой; (3) в сессиях
  Ok / Ok — доля ответов, где назван хотя бы один удачный прогон, в котором харнесс теперь делает иное (по номеру);
  (4) неверные утверждения о повторе — чтением выборки.

  только там, где сводка называет события (16), 11 ответов со сводкой совпали слово в слово, в 5 из трассы падения
  ушёл кадр `rerun_core.py`; остальное — чтение README и файлов `tests/`.

  ним была на тексте, вписанном руками; события «шаг не исполняется» и «сменился текст» на 9B; сессия целиком.
