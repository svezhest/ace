# ST4 — эталонные сессии: агент на Opus на месте писателя (тикет 10.11, шаг 4)

[Указатель проб](../INDEX.md) · хронология: [11.11](../days/1111.md) · тикет: [TICKET-1110-writer](../../TICKET-1110-writer.md)

- **Вопрос (тикет, шаг 4).** «Отделить "плохая постановка" от "модель не тянет". Где сильный агент на той же
  постановке делает то же, что 9B, виновата постановка». Слова автора 11.11: «агента запусти на opus», «запусти опус мы
  в ручном режиме».
- **Пробовали ли.** Нет. THIN (4–5.11) — свежий агент дорабатывал самого писателя, а не сидел на его месте. В
  [ST7 D1](../1110/ST7-D1-first-action.md) записано: «эталонного пути нет (шаг 4)». DS1–DS3 (11.11) — DeepSeek на
  месте писателя, но на других входах (эрзац-тикеты и отчёт о run 32), с лимитом bash 25 и 50.
- **Изменение.** Нет: база как есть (develop de981d5, виды `runs/typed_1111`, тикеты `docs/tickets_1106k`). За модель
  ходит агент Claude Code на Opus через почтовый ящик (`probes/1111/hand/`): один вызов на ход, поле `say` — протокол
  («что сказал прошлый ответ и зачем этот вызов»). Лимиты базы: bash 25, три хода после, окно по оценке знаков.
- **Входы.** Пять из разных клеток [ST3](../1110/ST3-input-map.md), по одной сессии: 01 (App, условие над историей,
  keep 8), 05 (App, текст промпта, keep нет), 06 (ALF, прямая починка, keep 3), 08 (ALF, условие над историей,
  keep 28), 09 (App, починка не названа, keep нет). Теги `o01`, `o05`, `o06`, `o08`, `o09`.
- **Чем отличается от писателя, кроме модели.** Агент видит описания инструментов текстом в первом сообщении ящика, а
  не полем `tools`; вызов пишет JSON-ом в heredoc; у него есть свои инструменты Claude Code (просьба — работать только
  через ящик; проверяется по его отчёту, не механикой); системный промпт Claude Code и пользовательские настройки
  ему видны, журналов и входов 9B в задании нет. Температура и рассуждение — как у агента, не как у базы.
- **Цена (до запуска).** Сессия — до 25 bash с выводом до 8000 знаков и 3–8 правок: к концу около 40–60 тыс. токенов
  разговора плюс обвязка агента; около 35 ходов × средний контекст 50 тыс. ≈ 1,5–2 млн входных токенов, почти все из
  кэша, и 10–20 тыс. выходных. Пять сессий — впятеро. Подписка, не API.
- **Мерка (глазами, по логу сессии и отчёту агента).** Путь (вызовы по порядку); трение стенда (вызовы только из-за
  наших инструментов); чего не хватило; где агент сделал то же, что 9B (README первым, чтение `tests/*.py`, правка
  на последнем bash, bash после конца). Итог правки — проигрышем итогового `src/` на всех прогонах вида.
- **Ожидание (до запуска, 04:56 по `date`).**
  - Все пять сессий кончаются finish, не лимитом; лимит bash 25 исчерпан не больше чем в одной.
  - Первый вызов — README (как у 9B) в пяти из пяти; исходники `tests/` читает не больше чем в двух.
  - 01: законный повтор в run 8 найден до первой правки либо сразу после первого «Failed: changes run 8»; итоговое
    условие различает по выводу или по падению прежнего шага, а не по расстоянию; проигрыш не задевает удачные.
  - 05: одна-две правки промпта, проверка Ok.
  - 06, 08: проверка Ok по тикету и по keep к концу сессии.
  - 09: правка есть, но уверенность агента в ней ниже, чем на остальных (починка во входе не названа).
  - Не сбылось, если: в двух и более входах нет Ok по тикету вместе с keep, или лимит bash исчерпан в большинстве —
    тогда дело во входе или стенде, а не в 9B, и это выносится автору.
