# KT — второй «убойный» тикет: настоящий отчёт ревьювера 9B о run 32 (ALF, вид alf_n4), 11.11

[Указатель проб](../INDEX.md) · хронология: [11.11](../days/1111.md) · первый случай — вход 01, [DS1](DS1-deepseek-ticket1.md), [DS2](DS2-deepseek-tickets2-5.md)

Разбор без модели, 04:10–04:20 по `date`. Слова автора: «попробуй найди другой такой же убойный тикет, как тикет по
этому прогону. только один».

- **Что искал.** Тикет того же устройства, что вход 01: симптом верен; объяснение называет место в коде и тем
  подсказывает починку; подсказанная починка задевает удачные прогоны; того, что различает прогоны, в тикете нет.
- **Что нашёл.** Отчёт настоящего ревьювера 9B, `tree_alf_1101` n4_0 #1 — вход 10 (`runs/typed_1110/in/10_real.txt`,
  мой тикет `docs/tickets_1110n/10.json`: control, run 32, keep 1). Его текст: «The `stalled()` guard only detects a
  stall when the last 3 actions were empty… `examine stoveburner 1`, which produced the identical observation twice
  in a row… Root cause: harness.py `stalled()` (lines 64-68) keys only on repeated empty actions».
  `stalled()` в этом виде — конец эпизода: «You are stuck… Stop now.» и `break`.
- **Проверка.** Копия вида (`tests/orig_src` → `src/`), в `stalled()` дописано по одному условию, проигрыш всех 40
  прогонов (10 проваленных, 30 удачных) `tests/rerun.py`:

  | прочтение починки | условие | run 32 | удачные прогоны, где харнесс теперь обрывает эпизод |
  |---|---|---|---|
  | осторожное, по образцу прежнего | то же действие три раза подряд | без изменений | 0 |
  | то же наблюдение три раза подряд | — | без изменений | 1 (run 2) |
  | словами отчёта: «identical observation twice in a row» | то же наблюдение два раза подряд | обрыв с вызова 2 | **12 из 30** |
  | то же действие два раза подряд | — | обрыв с вызова 40 | **14 из 30** |
  | самое узкое: то же действие **и** то же наблюдение два раза подряд | — | обрыв с вызова 40 | **3 из 30** (8, 31, 40) |

- **Почему так.**
  - В run 32 одинаковое действие подряд — только вызовы 39–41 (`examine stoveburner 1`), и на третьем эпизод
    обрывает мост (`repeated action`, REPEATS = 3). Поэтому «три подряд» в харнессе ничего не меняет, и проверка по
    тикету ответит «Failed: no effect in run 32» — писателя толкает сужать порог до двух.
  - В удачных прогонах повтор действия или наблюдения — обычное дело: run 8 — `open drawer 2` дважды, первый раз
    «is closed», второй «You open»; run 14 — `take cellphone 4 from bed 1` дважды с разным ответом; run 2 —
    `go to coffeemachine 1` и `examine coffeemachine 1` дают одно и то же наблюдение. После повтора модель идёт дальше.
  - Беда run 32 — 38 вызовов разных действий до первого повтора («went in circles reasoning»); повторами действий
    она не выражается, и место, названное отчётом, к ней отношения не имеет.
- **Чем этот случай жёстче входа 01.** Там подсказанная правка добавляла в двух удачных прогонах из четырёх
  сообщение. Здесь любое условие в названном месте, при котором run 32 меняется, **обрывает** от 3 до 14 удачных
  эпизодов из 30, а безвредное прочтение проверка отвергает.
- **Что не проверено.** На писателе этот вход не запускался ни разу (ни 9B, ни DeepSeek). «Обрыв» — расхождение
  повтора («the harness ends the episode here; the log goes on»): эпизод, удачный в логе, кончается раньше; что
  он стал бы проваленным, следует из того, что цель к этому вызову не достигнута, — по каждому прогону не сверял.
  Условия дописаны мной; что напишет писатель, неизвестно.
- **Второй просмотренный кандидат, не взят:** вход 13 (app n2_0 #3, run 8, «no guard against re-running an obviously
  failed code block»). Прочтение «упал и сразу повторён» run 8 не меняет; «повтор любого ранее упавшего кода»
  меняет run 8 и ещё 10 проваленных и задевает 1 удачный из 5 (run 30, законный повтор после установки токена).
  Слабее: один удачный прогон.
- **Данные.** Копии с правками — scratch сессии, `n10/` (`a_obs2`, `b_act2`, `c_act3`, `d_obs3`, `e_both2`) и `n13/`.
