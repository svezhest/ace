# EV30 — оценщик 9B с рассуждением без обрыва (бюджет 16384)

[Указатель проб](../INDEX.md) · тема: [оценщик](../../writer.evaluator.md) · прежние: [EV28](../1117/EV28-author-layout-9b.md),
[EV29](EV29-author-layout-haiku.md)

- **Повод.** В EV28 рассуждение `eval9t` обрезано бюджетом 2048 на 26 из 26. Автор (18.11): «почему в профиле писателя
  2к? разберись… сначала реши с бюджетом мышления. пересними 9б оценщика с расширенным мышлением».
- **Откуда 2048.** Профиль `stands/thinking.json` заведён 30.10 (2a61808) с `think_budget` 2048, и дальше значение
  наследовалось: `eval9t` (13.11) скопирован с него. Что бюджет режет, известно с 9.11 (MP3: «обрезано у всех 50»).
  Перебор 1–8 тыс. записан в TICKET-1110 и TASKS (шаг 9), но не сделан. У писателя `c9t` в EV27 упёрлись в бюджет 87
  ходов из 578 (15 %).
- **Решение по бюджету (18.11).** 16384, max_tokens 20480 (рассуждение входит в max_tokens) — для оценщика и для
  писателя. Рассуждение писателя в историю не кладётся (`nrhsi/editor/turn.py`, `record`), поэтому контекст от
  бюджета не растёт: платим только временем. Бюджет — предохранитель, а не клетка.
- **Что.** Те же 26 входов EV28/EV29 (`ev25_in/v2`), промпт `runs_v2`, T=0, профиль `eval9tx`. Стенд — серии EV27
  (`stand9p.sh`: q8 KV, предел 21 ГиБ, без драфтеров). Скрипт — `probes/1117/ev28.py eval9tx`. Идёт отдельным
  потоком рядом с серией EV31. Счёт — по разметке после поправки EV29 (25 правок: F 10, Ok 15).
- **Ожидание (18.11, 14:03 по `date`, до запуска).**
  - Длина рассуждения без обрыва: медиана 3–6 тыс. токенов. Упрутся в 16384 не больше 2 из 26.
  - Верно 14–18 из 25 (с обрезкой было 12; 27B — 19, Haiku — 20). Ложных Failed 3–6 из 15.
  - Четыре общих пропуска (03 ×2, 01 nl; 06 ck s2 поймал только Haiku) остаются.
  - Если ≥ 18 — 9B T как оценщик достоин отдельной серии. Если ≤ 13 — дело не в обрыве, дорабатывать шаг «факты →
    вердикт».
