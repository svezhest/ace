# EV29 — подача автора на Haiku 5.5 (через `claude -p`)

[Указатель проб](../INDEX.md) · тема: [оценщик](../../writer.evaluator.md) · прежние: [EV26](../1117/EV26-author-vs-ev6a-full.md),

- **Повод.** Автор (18.11): «давай планировать как улучшить оценщика, а то мы сели в лужу… предлагаю перезапустить 9б т
  и нт на тех же задачах, но в этот раз оценщик будет сильно лучше… так мы исключим влияние оценщика. если у нас при
  идеальном ответе от оценщика 7/10 будет — это повод думать». Кандидаты — DeepSeek flash и Haiku; автор: «дипсик
  придержи, запусти сейчас хайку». Сначала оценщик проверяется на размеченном наборе, потом идёт в серию писателя.
- **Набор.** Те же 26 правок кода, что EV26/EV28 (F 9, Ok 17), входы `runs/evw_1113/ev25_in/v2/`, промпт `runs_v2`.
- **Стенд.** `claude -p --safe-mode --setting-sources "" --model haiku --effort high --tools "" --system-prompt <runs_v2>`.
  Пробный вызов (18.11): модель claude-haiku-5-5, контекст обвязки 676 токенов, CLAUDE.md и инструментов не видно. Без
  `--safe-mode` в контекст попадали глобальный CLAUDE.md и язык ответа; `--bare` не входит по подписке. Температуру CLI
  не задаёт, один вызов на правку. Скрипт — `probes/1118/ev29.py`, 3 вызова параллельно.
- **Ожидание (18.11, 13:47 по `date`, до запуска).**
  - 20–23 из 26: Ok принято 15–17 из 17, F поймано 5–7 из 9.
  - Общие пропуски 27B и 9B (03 bl/ck — мёртвая ветка `output is None`, 06 ck s2 — нет `continue`, 01 nl) жду и здесь
    на 2–4 из 4: перепрогон их не показывает, нужно читать код правки.
  - Порог для серии писателя: ≥ 24 из 26. Если общие пропуски останутся, предел даёт вход оценщика, а не модель.
- **Итог (18.11, 13:22–13:53 по `date`, без ошибок вызова; модель во всех 26 — claude-haiku-5-5).** **19 из 26**: F поймано
  6 из 9, Ok принято 13 из 17. Ожидание (20–23) не сбылось по нижней границе. Порог серии (≥ 24) не пройден.
  - Впервые пойман один из общих пропусков: 06 ck s2 (нет `continue`, действие уходит в среду). 03 bl/ck (мёртвая ветка)
    и 01 nl пропущены, как у всех.
  - Ложные Failed — 00 cx, 01 cx, 04 cx, 06 nl. Первые три совпадают с ложными Failed 9B T. Доводы прочитаны, все
    четыре — по существу правки, а не по неверно прочитанному входу:
    - 01 cx: сообщение подставляет `memory["task"]`, а это первая строка `Task:` в промпте, то есть задача из примера
      («How many playlists…», `starting_prompt.md:29`). Модель в каждом прогоне получает чужую задачу. Сверено по diff —
      **дефект настоящий, моя метка Ok неверна**.
    - 06 nl s1: блок срабатывает и на пустом действии (ответ без вызова инструмента). Модель получает «не из списка»
      вместо «вызови инструмент». Довод правдоподобен, по прогону 36 не сверен — **спорно**.
    - 00 cx: проверка срабатывает в нужном месте, но после сообщения `break`, и модель сигнала не видит. Так устроен и
      исходный харнесс (стоп при stalled), так что это вопрос прочтения наблюдения, а не ошибка — метку Ok оставляю.
    - 04 cx: изменён текст старого сообщения на «хорошем» шаге run 14. Слабый довод, метка Ok.
- **Поправка разметки (18.11, после чтения доводов Haiku).** 01 cx s1: Ok → F. 06 nl s1: Ok → спорно (выпадает из
  счёта). Поправка внесена после ответов модели, но каждая сверена по коду. Пересчёт на 25 правках (F 10, Ok 15):

  | оценщик | было (26) | стало (25) |

  Сам набор меток — одна разметка (моя), и это её вторая ошибка за два дня. Остальные метки по доводам моделей не
  перепроверялись.
- **Вывод.** Haiku не хуже 27B и пропускает F реже. Но «идеальным» оценщиком он не стал: 5 ошибок из 25, и в трёх
  общих пропусках вход не показывает того, что нужно увидеть (мёртвая ветка, 01 nl). Серия писателя «при идеальном
  оценщике» с ним даст оценщика уровня 27B, а не идеального.
- **Что не пробовали.** Второй вызов на правку (T у CLI не задаётся, разброс неизвестен); `--effort` выше high; DeepSeek
  flash (автор: «придержи»); прямой вопрос о мёртвой ветке.
