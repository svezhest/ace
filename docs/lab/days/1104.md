## 17. Как писатель тратит bash, 4.11 вечер
- Скрипт: scratchpad `bash/an.py` (все 2638 вызовов bash из 110 сессий `runs/wvar_1104`; вердикт сессии — из READ.md).
- **Первая применённая правка — медиана на 25-м bash из 25**; на ≥20-м в 67 из 105 сессий с правками. У V медиана 19, у брака 25 (41 из 64 — ровно на лимите). Правку запускает сообщение о конце bash, а не решение писателя.
- Доли: src 26% (чтение 24, grep 2), логи 32% (сырые jsonl 12, python по логам 15, grep 5), проверки 23% (rerun 14, smoke 7, `--at` 2), чтение исходников инструментов (`tests/rerun_core.py`, `smoke.py`) 7% — в 67 из 110 сессий, свои симуляции с заглушками (import harness/hooks) 4% — 24 сессии, 62 из 99 падают на песочнице (запись в /tmp запрещена, `timeout` не разрешён, 20 с).
- По формам доля логов: (а) 53%, (б) 46%, (в) 34% — без строк логов во входе писатель тратит половину бюджета, восстанавливая их.
- rerun до первой правки (на нетронутом src) — 298 вызовов против 113 после; в 89 из 110 сессий. rerun N используется как читалка прогонов.
- Сырые jsonl через `sed -n` — 1/3 обрезана. Повторные чтения того же файла src — 160 лишних.
- **Исправление стенда:** время файлов в копии писателя одно (2026-11-01 00:00 UTC) — `ls -la` больше не разводит пары. Проверено: две копии с разницей в минуту — `ls -laR` совпадает.
