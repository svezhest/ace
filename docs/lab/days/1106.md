### Мерка: пары по месту расхождения (6.11, 14:26 по `date`, по вопросу автора о шуме суммы)
- **Шум взвешенной суммы за 10** (V = 1, P = 0,5, B = 0,25, x = 0; по TKS, TKV, TKW на 3 seed):
  - SD между seed одного варианта ≈ 0,64;
  - SD разности двух вариантов: ≈ 0,9 на одном seed, ≈ 0,5 по среднему трёх.
  - Чтобы различить варианты суммами, нужна разница около +1 балла на 10 сессий. Наши разницы +0,4…0,7, это шум. Парная перестановка знаков: TKW против TKV p ≈ 0,49, TKS против TKV p ≈ 0,40.
- **Пары.** Сессии с одним seed совпадают до первого отличия входа. Скрипт `editor/pairs_tk.py` находит первый ход с разным ответом модели и первый отличающийся вход писателя до него. Вход считается механизмом, только если это вывод проверки после правки («Checks run on src/», «Check against the observation») или заметка о bash. Даты и имя сессии при сравнении вырезаются.
- **Посторонние причины расхождения — две:**
  1. **Даты в `ls -la`.** Каталоги копии создаются в разное время, модель видит разные даты, и сессия с тем же seed идёт иначе с первого хода. Часть того, что я называл «шумом сервера», на деле вот это.
  2. **Длина `tests/rerun_core.py`** (мой конфаунд до заморозки копии, TKS s1/TKC/TKL, TKS_s2 04–09).
  - Чистый шум сервера (все входы совпали, ответ разный) — ход 2–8, примерно 1–2 пары на серию.

### Ещё три места промпта писателя (6.11, 15:23 по `date`, по вставке автора)
1. **«Готово» не определено.**
   - «finish… when you are done» встречается трижды: два раза в системном промпте и последней строкой первого сообщения.
   - Замер по 193 сессиям TK*: последняя проверка Ok — сам finish в 74 из 122 (61 %); Failed — в 20 из 67 (30 %).

2. **В тикете только «что должно измениться»** (FAIL_TO_PASS). Нет половины «что должно остаться» (PASS_TO_PASS в SWE-bench). Ревьювер может назвать 1–2 контрастных прогона (для 01 — законный повтор в run 8), а не весь класс. Это правильная форма поправки про TKP.
