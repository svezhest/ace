# EV25 — подача автора на правках, где EV6a ошибся

[Указатель проб](../INDEX.md) · тема: [оценщик](../../writer.evaluator.md) · прежние: [EV12](../1113/EV12-author-layout.md),
[EV20](../1114/EV20-author-layout-on-writer.md), разметка — [O4-writer-labels](O4-writer-labels.md)

- **Повод.** Автор (16.11): «хочу попробовать запустить свой оценщик на входах, где ev6a провалился». В EV20 обе подачи
  ошиблись на одних и тех же правках, поэтому равенство 18 из 20 ничего не говорило о том, где они расходятся.
  Здесь набор — только провалы EV6a.
- **Набор (9 итоговых src, метка — моя разметка по diff).**

  | тег | метка | что EV6a сказал | откуда |
  |---|---|---|---|
  | 00_ck_o4_s1 | Ok | Failed: круг take / take в проваленном run 4 назван «прогрессом» | сессия писателя, oQ4e |
  | 00_ck_o4_s2 | спорно | Failed: то же место | сессия писателя, oQ4e |
  | 03_bl_o4_s1 | F | Ok: ветка `output is None` мертва, упавший шаг назван успешным | сессия писателя, oQ4e |
  | 03_ck_o4_s1 | F | Ok: то же | сессия писателя, oQ4e |
  | 06_ck_o4_s2 | F | Ok: нет `continue`, действие уходит в среду | сессия писателя, oQ4e |

  | 06_nl_s1 | Ok | Failed на q5, Ok на oQ4e | EV20, EV22 |

  | 07_nl_s1 | Ok | Ok на q5, Failed на oQ4e (неверно прочёл описание перепрогона) | EV20, EV22 |

  В счёт идут 8 (00_ck_o4_s2 спорно — смотрю только довод).
- **Что сравнивается.** `v2` (подача автора, промпт `runs_v2`) против `ev6a` (`--blocks`, промпт `runs`), обе собраны
  одним скриптом `probes/1116/ev25.py` в два шага: `build` без модели (16.11, 14:50) и `call` — 27B `plain27`, T=0, один
  вызов. Входы сверены: `ev6a` 00_ck_o4_s1 — 5533 знака, ровно как вход оценщика в сессии писателя; четыре старых тега
  совпадают по длине с EV20 у обеих подач. Входы — `runs/evw_1113/ev25_in/<var>/<тег>.txt`; `v2` в 1,2–2,3 раза длиннее
  (до 153 тыс. знаков на 06).
- **Почему ev6a тоже заново.** Набор выбран по ошибкам EV6a, и повтор на T=0 их, скорее всего, повторит — но у трёх тегов
  ошибка была только на одном стенде. Без парного вызова провал подачи автора не отличить от провала стенда.
- **Ожидание (16.11, 14:52 по `date`, до запуска).**
  - `ev6a` повторит свои ошибки на 7–9 из 9 (T=0, тот же стенд для пяти тегов oQ4e).
  - `v2` верна на 3–5 из 8. Довод: в EV20 подачи ошибались на одних и тех же правках; заголовок «previously NOT OK,
    50 steps» на 00 должен помочь (run 4 и так провален — это прямо в заголовке), а мёртвую ветку 03 и отсутствие
    `continue` в 06 перепрогон не показывает ни в одной подаче — тут жду те же пропуски.
  - Если `v2` верна на ≥ 6 из 8 — повод проверить её в сессии писателя; если ≤ 2 — подачи в этом месте равны.
- **Стенд.** Веса oQ4e, но рецепт новый: стенд поднят llm-81 17.11 в 10:44, llm main 2df454b. Отличия от сессий писателя —
  `QWEN_KV_BITS=8 QWEN_KVQ_PREFILL_FUSED=1 QWEN_DECODE_ATT=8192 QWEN_DRAFT=auto` (было fp16 KV и DFlash2). Это другой
  класс численности: при T=0 ответ не обязан совпадать с прежним. Из-за этого парный вызов `ev6a` здесь обязателен, и
  ожидание «повторит свои ошибки на 7–9» оценивает заодно, насколько переносится стенд. Запуск 17.11 в 15:03 по `date`.
  Вызовы оценщика идут с `prompt_cache=read`.
- **Шум сборки.** Первая сборка 00_ck_o4_s1 упала: перепрогон отдал пустой stdout (как 14_ev_s3 в EV22 на q4); повтор
  прошёл, все 18 входов собраны. Причина не найдена.
- **Итог (17.11, 15:03–≈16:40, оба прохода без ошибок шлюза).**

  | тег | метка | v2 | ev6a | ev6a на прежнем oQ4e |
  |---|---|---|---|---|
  | 00_ck_o4_s1 | Ok | **Ok** | Failed | Failed |
  | 00_ck_o4_s2 | спорно | Failed | Failed | Failed |
  | 03_bl_o4_s1 | F | Ok | Ok | Ok |
  | 03_ck_o4_s1 | F | Ok | Ok | Ok |
  | 06_ck_o4_s2 | F | Ok | Ok | Ok |
  | 01_nl_s1 | F | Ok | Ok | Ok |
  | 06_nl_s1 | Ok | Ok | Ok | Ok |

  | 07_nl_s1 | Ok | **Ok** | Failed | Failed |

  - Верно: `v2` 4 из 8, `ev6a` 1 из 8. Ожидание для `v2` (3–5) сбылось, порог «≥ 6 — в сессию писателя» не достигнут.
  - `ev6a` на новом стенде (q8 KV, DRAFT=auto) дал те же вердикты, что на прежнем oQ4e, на всех 9 тегах. Новая
    численность вердикт оценщика здесь не сдвинула; ожидание «повторит 7–9» сбылось.
  - Где `v2` лучше, это только ложные Failed `ev6a` (3 тега). Пропуски F у обеих подач одни и те же (4 из 4), а доводы
    на 03 совпадают почти дословно: «edit correctly distinguishes … (output is None)». Мёртвую ветку не видит ни одна.
  - Доводы `v2`, где она права:
    - 00 s1 — run 4 прочитан верно, как застревание на круге take / take, а `ev6a` назвал его «прогрессом»;
    - 07 nl — описание перепрогона прочитано верно, а `ev6a` прочёл «harness does the same» как «`continue` не сработал»;
    - 06 ev — в строке Where пусто: вердикт верен, но довода нет. `ev6a` там приводит конкретный и ложный довод: «open
      drawer 2» у drawer 1 среда «выполнила верно», хотя на деле подменила на «go to drawer 2».
  - Перекос: `v2` сказала Failed 1 раз из 9 (только на спорном 00 s2), `ev6a` — 4 раза. Набор из провалов EV6a почти
    наполовину состоит из ложных Failed, и подача, склонная к Ok, на нём выигрывает сама собой. 4 из 8 — это не
    довод, что `v2` лучше разбирает правку; она реже бракует.
- **Что не пробовали.** `v2` на правках, где `ev6a` прав, особенно на F, которые он ловит (без этого перекос к Ok не
  отличить от лучшего чтения); второй seed / перестановку блоков; `v2` с рассуждением; подсказку о мёртвой ветке —
  видит ли модель `output is None` при прямом вопросе.
