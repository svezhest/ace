# EV41 — оценщик 9B на прогон: сначала правило из наблюдения, потом шаг по нему

[Указатель](../INDEX.md) · [EV40](EV40-eval9-quote-evidence.md)

- **Гипотеза.** В EV40 9B видит факты (действия нет в списке), но вывод «шаг в порядке» берёт из нормального ответа
  среды, а не из того, что наблюдение называет проблемой. Если сначала записать своими словами, по какому признаку шаг
  относится к проблеме из наблюдения, а затем проверить шаг по этому признаку, вывод пойдёт от правила.
- **Что.** Форма ответа вызова на прогон (вместо выписки EV40): «First write, in one sentence, what the observation says
  makes a step part of the problem. Then check this step against it, using what the input shows. Then write one line:
  …». Описание шага EV39 оставлено.
- **Мерка.** Те же 12 вызовов: 06_bl run 4 / 5 / 9, seed 11–14.
- **Ожидание (21.11 08:09, до запуска).** Ошибочных строк 2–5 из 12 (было ~6, ~8, ~7–8). Если 6 и больше — ступень
  «правило вперёд» не перебивает видимость нормального ответа; тогда эта ошибка 9B на прогоне устойчива к форме ответа.
- **Итог (21.11 08:22).** Ошибочных строк 5 из 12 (run 4 — 4 из 4, run 5 — 1, run 9 — 0) против ~6 / ~8 / ~7–8. В ожидание
  (2–5) попало на краю. Правило 9B выписывает верно во всех 12 («not in the list of available actions»), run 5 и run 9
  теперь проверяет по нему. Run 4 упорен: «the Env at step 43 lists … examine drawer 1» — список из ответа на сам шаг,
  вопреки фразе EV39; список шага 42 во входе обрезан (… +25 more lines), полный — только в Diff.
- **Что это значит для разбивки.** Даже при ~40 % ошибочных строк на 06 сборка «одна плохая строка — Failed» по 27
  прогонам даёт Failed почти наверняка; разбивка требует ошибки строки порядка 1–2 %, на 9B недостижимо. Дальше —
  ступени EV39 + EV41 на целом входе (EV42), где модель видит все прогоны сразу.
