# EV43 — вход v3: два шага перед местом расхождения без обрезки

[Указатель](../INDEX.md) · [EV42](EV42-eval9-whole-with-steps.md)

- **Зачем (автор 22.11: «стоп, что? разве не даём всё на вход?»).** Не всё: `render_raw` режет каждое сообщение
  среды/харнесса до 6 строк (с EV4, 13.11). На 06 решающее — список действий, который модель видела перед шагом; во
  входе от него 6 строк из ~31, полный — только в Diff. 27B выводит «действие не из списка» косвенно, 9B берёт список
  из ответа на сам шаг. Гипотеза: ступени EV42 закрыли дыру нашего входа, а не логику 9B.
- **Что.** `ev_input.FULL_LAST = 2` (вход v3, `probes/1116/ev25.py build v3`): шаги K−2 и K−1 перед местом —
  сообщения до 80 строк. Сверено: v3 отличается от v2 только снятыми строками «… (+N more lines)» (26 из 26). Длина
  +5–15 % (06: 142–155 -> 164–177 тыс. знаков).
- **Мерка.** 9B eval9e_med, `ev42.py` на v3: base seed 1–3, both seed 1–3 (stand9q). Затем 27B plain27 (T 0, NT,
  stand27c): base и both на v3 по одному вызову (seed 1) — планка на новом входе. Сравнение — с EV42 на v2 (base 14,3,
  06 — 4 из 15; both 16,7, 06 — 11 из 15) и 27B EV26 (19).
- **Ожидание (22.11 05:19, до запуска).**
  - 9B base v3: 06 — 8–12 из 15 (было 4), среднее 15–17. Если 06 ≤ 6 — обрезка не главное, ступени делают своё.
  - 9B both v3: среднее 16–18, 06 — 10–13; разница both − base ≤ 1 (дыра закрыта входом, ступени лишние).
  - 27B base v3: 18–21 (было 19); 27B both v3: 18–21. Если ступени роняют 27B на ≥ 2 — они клетка для сильной модели.

  теперь при видимом списке: s2 06_bl — «valid_actions under-reports the accepted actions (it lists go to drawer 2
  without the open drawer 2 the environment actually offers)»: раз среда приняла действие, неверен список, а не
  действие. Это логика (нормальный ответ среды перекрывает правило), не нехватка входа. Ожидание (06 base 8–12) не сбылось.
