## 10.11, 00:18 по `date` — стенд thinking и проба MP3: те же вопросы MP с thinking

- **Автор:** «ну хорошо, включи thinking, уговорил».
- **Стенд.** Профиль `stands/thinking.json` (2211bd9265028d53) как есть: второй шлюз `:8081` без `GATEWAY_THINKING=off`, поднят командой из профиля (pid 84070, лог /tmp/qwen-gateway-8081.log); агент T 0,6, max_tokens 4096, thinking_budget 2048. Воркер и шлюз `:8090` не тронуты. `stand._probe`: think — reasoning есть (18 токенов из 80), main — нет.
- **Отступление от правила сверки.** `stand.check` падает: на `:8081` два слушателя — шлюз (127.0.0.1) и чужой `expo start --port 8081` (node, pid 6448, с 8.11, проект adapty-hackathon, слушает `*:8081` по IPv6). Expo не трогаю. Запрос на 127.0.0.1:8081 приходит в шлюз (проверено probe и ответом с reasoning). В скрипте пробы параметры берутся из профиля через `stand.gen`, без `check`; для сессий через `apply_stand` это не годится — там нужен свободный порт или другой порт в профиле (решение автора).
- **Гипотеза.** Годные ответы MP и MP2 пришли из длинных рассуждений (8 из 31 против 4 из 109). Если длина — причина, thinking поднимет долю годных на тех же вопросах.
- **Изменение.** Только стенд: батарея MP (`battery.json`) без плеча F, те же seed, плечи 08 A, 08 C, 08 R, 01 A, 01 R × 10 = 50 вызовов; дозапрос при обрыве по длине как в MP. Рассуждение сохраняется.
- **Мерка.** Как в MP; сравнение с MP по плечам (off: 0, 1, 0, 0, 2 — всего 3 из 50). Сначала — что thinking включился: токены рассуждения в каждом ответе, доля ответов, где бюджет 2048 исчерпан, доля обрывов по длине.
- **Ожидание (до замера).** Рассуждение в 50 из 50, бюджет исчерпан в большинстве. Годных всего 8–12 из 50, если длина — причина; ≤ 5, если нет. По плечам: 08 A 2–3, 08 C 3–4, 08 R 1–2, 01 A 0–1, 01 R 3–5. Моя уверенность, что будет ≥ 8, около половины.
- **00:24 по `date`:** автор погасил expo; на `:8081` один слушатель (шлюз 84070), `stand.check('thinking', agent)` проходит. Отступление выше больше не нужно; идущая MP3 запущена до этого, на том же шлюзе.
- **Итог MP3, 10.11, 00:55 по `date`** (`out3.jsonl`, `ev3.jsonl` в scratchpad сессии; прибор — как в MP, глазами прочитаны только кандидаты).
  - Механизм включился: рассуждение в 50 из 50, у всех ровно 2050 токенов — бюджет исчерпан в каждом ответе. Обрывов по длине 4 из 50, 136 с на ответ.
  - Годных по прибору (тикет задет, keep цел): 08 A 1, 08 C 1, 08 R 2, 01 A 0, 01 R 0 — всего 4 из 50 против 3 из 50 без thinking. Ожидание «8–12, если длина — причина» не сбылось, сбылось «≤ 5».
  - Глазами: 08 A k1 и 08 C k10 — подсказка под одну задачу («Look under the desklamp for the cd», счёт действий со словом desklamp): по мерке автора это мимо, не годная. 08 R k10 — настоящий детектор периода (пары действие+наблюдение, период ≥ 2, два повтора). Остаётся 2 из 50 (08 R k4 целиком не читал).
  - Побочное: слова задачи в коде правки (desklamp, dresser, cd) на 08 — 14 из 30 с thinking против 8 из 30 без (плечи A, C, R; счёт регуляркой по блокам кода).
  - 01 A: 8 из 10 — одна и та же правка «код уже был в истории», задевает тикет на вызове 11 и удачный run 8 на вызове 10.
- **Вывод.** В формате одного вопроса thinking с бюджетом 2048 долю годных не поднял и чаще зашивает слова задачи. Связь «длинное рассуждение → годный ответ» из MP и MP2 причинной не подтверждается. *Средняя* для этого формата и бюджета.
- **Не проверено:** бюджет больше 2048 (сейчас рассуждение обрезано у всех 50); thinking в агентском режиме, где есть чем проверять; все 50 ответов глазами по шкале «точно / частично / мимо / поломано»; второй набор seed.
