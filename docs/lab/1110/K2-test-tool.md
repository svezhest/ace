- **K2 (постановка).** Гипотеза: если 9B может *проверить* условие на обоих прогонах, а не утверждать, доля верных
  вырастет. Изменение: прототип `fk/cond/k2.py` (кода в репозитории нет) — тот же запрос, плюс инструмент
  `test(condition)`: выражение Python над `step` и `earlier` вычисляется на каждом шаге run 40 и run 28, в ответе —
  номера шагов, где истинно. До 8 ходов, бюджет 4096, 10 сессий. Прогоны 40 и 28 берутся из тикета. Проверка без

  шаги цикла) и совпадает ли фраза с проверенным выражением.
- **Ожидание (до замера).** Последнее проверенное условие чисто разделяет прогоны у 7 из 10; фраза ему соответствует у 6.

## 10.11, 16:35 — K2 прочитана: как поставлена — не работает; K3 постановка

- **Итог K2** (16:19–16:35). Итоговой фразы за 8 ходов нет ни у одной из 10. Чистое структурное условие нашли 2
  (#3: «ответ равен ответу через один» — 45 и 0; #4: «…и через три» — 42 и 0), но не остановились.
- **Ожидание не сбылось** (ждал 7 и 6). Причины, три из них мои:
  - ошибка прототипа: в `eval` раздельные пространства имён, генераторы не видят `step` (`NameError` у #1, #4, #6);
  - в запросе K2 не было списков шагов (в K1c были) — модель тратила ходы на разведку (`True`, `len(earlier) >= 1`);
  - `IndexError` на первом шаге: 17 проверок из 104;
  - **содержательное:** инструмент поощряет буквальные условия. `step.action == "examine dresser 1"` даёт 23 и 0, и
    мерке «истинно в run 40, нигде в run 28» это удовлетворяет. Таких проверок большинство у 6 из 10. Два прогона не
    отличают общее условие от зашитого.
