# ST3N — новые входы из отчётов настоящего ревьювера (тикет 10.11, шаг 3)

[Указатель проб](../INDEX.md) · хронология: [10.11](../days/1110.md) · тикет: [TICKET-1110-writer](../../TICKET-1110-writer.md) · карта прежних входов: [ST3](ST3-input-map.md)

Разбор без модели, 10.11, 20:35 по `date`. Писатель на этих входах не запускался ни разу: правило отбора записано
до того, как видно, что он с ними делает. Ответ автора на вопрос 1 («да») передан через сессию itmo-42, в этой
сессии не подтверждён; входы — файлы, базу не меняют.

## Правило отбора

1. **Источник** — отчёты сессий ревьювера на узлах, у которых уже есть типизированный вид: `tree_alf_1101` n4 →
   `runs/typed_1110/alf_n4` (40 прогонов) и `tree_app_1101` n2 → `app_n2` (30 прогонов). Других узлов не беру:
   перенос узла на типы — ручная работа (TY). Это ограничение набора: два вида, шесть сессий (n4_0–n4_2, n2_0–n2_2).
2. **Кандидаты** — отчёты вида `problem`, в которых назван прогон (без прогона нет тикета). Порядок: сессии 0, 1, 2,
   внутри сессии — по номеру отчёта. Всего 12 (ALF) и 13 (App).
3. **Разметка** — моя сверка со строками вида и логов, по несущему утверждению: верное; верный симптом с выдуманным
   механизмом; неполное (симптом и прогон есть, места в `src/` или механизма нет); ложное; о том, чего харнесс
   изменить не может. Вердикты разметки 2.11 (`runs/review_reviewers.md`) по отчётам не сохранились, есть только
   сводка; сверено заново.
4. **Беру первый по порядку отчёт каждого из трёх видов на бенч.** Вида нет — так и записываю.
5. **Текст — как написал ревьювер** (наблюдение и evidence, в форме, в какой дерево отдаёт отчёт писателю).
   Правятся только ссылки на код: номера строк и имена, которых в типизированном виде нет. Фраза, цитирующая
   комментарий, которого в виде нет (виды без комментариев), вырезается. Все замены — списком в
   `probes/1110/s3/new_inputs.py`, каждая обязана встретиться ровно один раз.
6. **Тикеты мои** (`docs/tickets_1110n/`) — верхняя граница: прогон из наблюдения; тип — control, если наблюдение о
   том, что код харнесса не реагирует, иначе any; keep — как у прежнего входа на том же виде (ALF: run 1; App: нет).
