## 10.11, 03:31 по `date` — H1/H2: падение кода на одном ходу (развилка g3_r3, ход 17; 4 плеча по 10 ответов)

- **Откуда.** Автор: «больше ручных проб». По каталогу журнала значения и типы в сообщении о падении не пробовали; факт со значениями был только у мёртвого условия (TKV).
- **Развилка.** G3 #3 после первой правки: `steps = (now.earlier_steps, now.step)` (пара вместо списка шагов), все 29 прогонов падают с `AttributeError: 'tuple' object has no attribute 'action'` на `src/hooks.py:20`. В самой сессии причина не найдена за три хода. bash кончился, ход без bash (`fork.py --final`).
- **Плечи** (`fork.py --last`, ответ проверки правлен вручную, кода в репозитории нет):
  - база — как в логе;
  - locals — под строкой упавшего кадра его локальные переменные в форме `traceback` с `capture_locals` (`steps = ((), Step(...))`, `a = ()`, `b = Step(...)`), значения из первого шага run 1;
  - без pyflakes — убраны обе строки «'re' imported but unused»;
  - без pyflakes + locals у обоих кадров hooks.py.
- **Ожидание (до замера):** база чинит причину не более чем в 3 из 10, с locals — в 6–8.
- **Итог** (ручное чтение 40 правок):

  | плечо | что сделано следующим ходом | причина (строка 36) исправлена |
  |---|---|---|
  | база | 10 из 10 убирают `import re`; 4 — только это, 6 переписывают `_looping` без изменений | 0 |
  | locals | 10 из 10 убирают `import re`; 5 ставят охрану на упавшей строке (`getattr`, `hasattr`) | 0 |
  | без pyflakes | 10 из 10 меняют замысел: другой детектор («было раньше», «N одинаковых подряд») на той же паре | 0 |
  | без pyflakes + locals | 10 из 10 ставят охрану на упавшей строке (`hasattr`, `getattr`, `isinstance`, `list(steps)`) | 0 |

- **Ожидание не сбылось:** причину не исправил никто из 40.
- **Что видно.**
  - Предупреждение pyflakes забирает ход целиком: 20 из 20 начинают с него, 4 из 10 им и ограничиваются, при трёх ходах без bash.
  - Правится строка, на которую указывает трассировка, а не строка, где значение построено. Строки 36 в трассировке нет: там 37 (вызов) и 20 (падение).
  - Значения переводят «сменить замысел» в «заглушить падение»: падение превращается в мёртвое условие. Для точности реализации это не лучше.
  - Значение `steps = ((), Step(...))` прочитано как «earlier_steps пуст» (#4: «handle the case where earlier_steps is empty»): на первом шаге пара и пустой список неразличимы.
- **Сколько таких сессий** (офлайн, 28 сессий G3–G5): текущий шаг с прошлыми склеивают 2, из них с ошибкой 1. Поле «все шаги с текущим» в `AfterStep` этим не оправдано, из очереди снимаю.
- **Вывод.** Локальные переменные в трассировке причину не открывают. Отдельно: предупреждение линтера рядом с падением отнимает ход — кандидат на правку порядка или состава проверок (не сделано, сначала проверить на втором падении). *Средняя* по pyflakes (20 из 20, одна развилка), *низкая* по locals (одна развилка, один вид ошибки).
- **Не проверено:** другие падения (`'Step' object is not subscriptable`, `UnboundLocalError`); падение не на первом шаге; ход с bash; thinking на этой развилке.

## 10.11, 05:04 — pyflakes и падение: обзор по сессиям вместо новой развилки

- **Откуда.** H1/H2: на g3_r3 предупреждение pyflakes забирало ход, причина падения не исправлена 0 из 40. Хотел
  проверить на втором падении; подходящих развилок с моделью не понадобилось — прочитал все ответы проверок, где есть и
  падение, и pyflakes (G3, G4, G5, G7: 10 случаев).
- **Итог.** В 9 из 10 следующий ход чинит причину падения. В 4 из них предупреждение — та же причина
  (`undefined name`), в 5 — постороннее (неиспользуемые импорты, переопределения), и оно ходу не мешает. Единственный
  случай, где ход ушёл на pyflakes, — g3_r3, и там причина падения не в строке из трассировки.
- **Вывод.** «pyflakes забирает ход» не общее свойство; порядок проверок менять незачем. От H1/H2 остаётся второе:
  правится строка из трассировки, а не место, где построено значение (один случай).
