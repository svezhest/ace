# EV32 — оценщик 9B с рассуждением: выборка из карточки вместо T=0

[Указатель проб](../INDEX.md) · тема: [оценщик](../../writer.evaluator.md) · прежние: [EV30](../1118/EV30-eval9t-full-budget.md),
[EV29](../1118/EV29-author-layout-haiku.md)

- **Повод.** EV30: при T=0 рассуждение 9B зацикливается, 24 из 26 вызовов упёрлись в бюджет 16384. Автор (19.11):
  «Оценщик работает с температурой 0 — это никем не вынуждено. разбери».
- **Разбор: откуда T=0.**
  - `stands/eval9.json` и `eval9t.json` заведены 13.11 (1f6d870, EV13) с припиской «агент T=0 — для оценщика правки,
    как plain27 / think27 у 27B». Своего довода у 9B нет — значение скопировано.
  - У 27B T=0 держался ради скорости: драфтер DFlash идёт только при жадном декодировании (`think27t.json`: «драфтер при
    T≠0 не работает»; `~/Projects/llm/src/worker/qwen_worker/config.py`: «only used when the request is greedy»). На
    `stand9p.sh` драфтеры выключены (`QWEN_DRAFT_DFLASH=none`, `QWEN_DRAFT_MTP=none`) — довод и тут не действует.
  - Воспроизводимость одного ответа T=0 даёт, но это и есть одна точка: разброс оценщика не мерился ни разу
    (writer.evaluator.md: «один ответ на правку при T=0»).
  - Карточка модели (`weights/ornith15-9b-mlx-8bit/README.md`, «Recommended sampling parameters»): общие задачи — T=1,0,
    top_p 0,95, top_k 20, min_p 0, presence 1,5; точный код — T=0,6, top_p 0,95, top_k 20, presence 0. Комментарий стенда
    (`config.py`): «For reasoning / benchmarks set QWEN_PRESENCE_PENALTY=0 and the card's sampler (thinking:
    temperature 1.0, top_p 0.95, top_k 20, min_p 0)».
  - Что шлём сейчас: `ev_judge.call` и писатель (`nrhsi/researcher/model.py`) передают только temperature и seed.
    top_p, top_k, min_p берутся по умолчанию стенда — выключены (1,0 / 0 / 0); presence 0 (`stand9p.sh`).
  - **Писатель тоже не по карточке.** T=0,6 (с 03.11, «агенты метода T=0.6»), но без top_p 0,95 и top_k 20 — выборка
    из всего хвоста. Здесь не меняю: это стенд всех серий писателя; предложение автору.
- **Версия.** Профиль `stands/eval9tc.json`: как `eval9tx` (бюджет 16384, max_tokens 20480), T=1,0 и
  `sampling` {top_p 0,95, top_k 20, min_p 0, presence 0}. `ev_judge.call` кладёт `agent.sampling` профиля в запрос
  (у прежних профилей ключа нет — запрос прежний). `ev28.py <stand> <seed>`.
- **Что.** Те же 26 входов (`ev25_in/v2`), промпт `runs_v2`, seed 1, 2, 3 — три процесса параллельно на одном стенде
  (`stand9p.sh`, без писателя рядом). Счёт — по разметке после поправки EV29 (25 правок: F 10, Ok 15), на каждом seed
  и большинством из трёх.
- **Ожидание (19.11, 11:03 по `date`, до запуска).**
  - Циклы уходят: в бюджет упираются не больше 5 из 26 на seed (было 24); медиана выхода 3–8 тыс. токенов; доля
    повторённых строк у неупёршихся < 20 %.
  - Верно 15–19 из 25 на seed (T=0 — 17). Большинство из трёх — 17–20. Разброс между seed — 2–4 вердикта из 25.
  - Общие пропуски (03 bl/ck — мёртвая ветка, 01 nl) остаются: дело во входе, не в декодировании.
  - Если циклы не уйдут — дело не в жадности, а в самой задаче для 9B (две трактовки «fine steps»).
- **Ход.** 11:04–20:21 по `date`, без ошибок вызова. 18:44–20:00 — перерыв GPU по просьбе автора: стенд погашен
  (`ev32_pause.sh`), прерванные вызовы повторены после подъёма (ev28.py пишет только законченные). 78 из 78 строк.
- **Итог.** Счёт по 25 правкам (F 10, Ok 15), разбор — `scratchpad`-скрипт, логика как в EV29:

  | | верно | ложных Failed | пропусков F | без вердикта | упор в бюджет (рассуждение ≥ 16000) | медиана вывода | повтор строк, медиана |

  | s1 | 14 | 5 | 4 | 2 | 21 из 26 | 17,1 тыс. | 10 % |

  - Ожидание сбылось наполовину. Циклы ушли: повтор строк 9–11 % против 57–90 %, максимум 27 %. Но упор в бюджет
    остался (16–21 из 26 против ≤ 5 ожидаемых), медиана вывода — 17 тыс., а не 3–8. Верно 14–17 на seed, большинство
    16 — ниже ожидания (17–20) и не лучше T=0 (17). Разброс 3 — в ожидании.
  - Почему упор без циклов (прочитаны 03 bl s2, 04 bl s2): рассуждение не повторяет строки, а ходит по кругу смыслом —
    «But wait, let me reconsider», «Actually, you know what, let me reconsider the whole thing», каждый раз с новой
    формулировкой. Обрыв на 16384 приходится на середину очередного пересмотра; ответ после обрыва связный и с
    вердиктом. То есть циклы T=0 сменились долгим колебанием, а не решением.
  - Общие пропуски остались у всех трёх seed: 03 bl/ck (мёртвая ветка `output is None` — 03 bl s2 прямо пишет «I'm now
    worried about the `output is None` semantics» и снова принимает), 01 nl, 01 cx (задача из примера, её поймал только
    Haiku). 06 ck s2 пойман на 2 из 3 seed — его не ловил 27B.
  - Ложные Failed: 04 bl на всех трёх (довод «правка поменяла текст сообщения на шаге, который старый харнесс уже
    ловил, — это задетый удачный шаг»: та же граница «fine steps», что у Haiku на 04 cx), 00 ck на 2 из 3.
  - Девять правок из 25 расходятся между seed — вердикт 9B на них решает выборка.
- **Вывод.** Выборка по карточке убирает зацикливание, но не точность: 9B T с 16384 — 16 из 25 большинством (27B NT —
  19, Haiku — 20). Бюджет 16384 почти всегда исчерпан — рассуждение не сходится, а колеблется. Отставание от 27B — 3.
- **Что не пробовали.** Фразу уровня effort в начале системного сообщения (родная Qwen 3.8, ветка llm-81
  `effort-levels`); бюджеты 1024/4096/8192 с выборкой; presence penalty; рассуждение 27B на тех же входах как образец;
  разбор девяти правок, решаемых выборкой; вход оценщика под 9B (общие пропуски — вход не показывает нужного).
