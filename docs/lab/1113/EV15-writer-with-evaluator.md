# EV15 — писатель с оценщиком на finish

[Указатель проб](../INDEX.md) · хронология: [13.11](../days/1113.md) · тема: [оценщик](../../writer.evaluator.md) · прежние: [EV13](EV13-new-set.md), [EV14](EV14-prompt-by-fact.md)

- **Повод.** Автор (13.11): «выбери, которая лучше… 13-й или 6-й вариант… пробуй с писателем прогнать, ну там
  каких-нибудь 20 правок. То есть писатель вместо работы с реран и тому подобного должен обращаться к оценщику… когда ок,
  он завершается, когда не ок, он правит то, что дает оценщик».
- **Выбор подачи — EV6a** (`--blocks --prompt runs`): на t1/08 36 из 40 против 32 из 40 у EV12; на наборе EV13 логика
  обе 5 из 7. Промпт — отдельным вызовом, по факту (EV14, 4 из 4).
- **Пробовали ли.** Оценщика в сессию писателя не встраивали; мерили только на готовых правках (EV3–EV14).
- **Что поменялось** (ветка `feature/writer-evaluator`, 7b83564; сессии идут из её копии `~/Projects/nrhsi-we`):
  - `finish` → `nrhsi/editor/review.py`: две части, каждая своим вызовом `plain27` (27B NT, T=0): логика — вход EV6a с
    перепрогоном после промпта (полный вид `runs/full_1112/<вид>`, шаги из `runs/evw_1113/chk/<вид>`); промпт —
    сообщения до шага 1 до и после. Ok — все непропущенные части Ok: сессия кончается. Иначе писатель получает: «Not
    finished yet. A reviewer checked your change against the observation. It does not accept it yet.», ответ оценщика по
    каждой непринятой части как есть, строку о принятой части, «Change src/ with edit where the reviewer points, then call
    finish again.» Без изменений в src/ — конец сразу. Предохранитель — 6 вердиктов (писателю не печатается).
  - после правки — только ответ edit (изменённые строки, pyflakes); smoke, rerun и проверка по тикету убраны; в копии нет
    `tests/rerun.py` и `tests/smoke.py`, в README — только `tests/runs.py`; тикет не подаётся.
  - системный промпт: finish — «submit your changes when they are done. A reviewer checks them against the observation…»;
    строка о проверках после правки убрана.
  - `ev_input.build_from` / `build_prompt_from` — сборка входа по готовым файлам; входы EV13/EV14 от этого не изменились
    (сверено символ в символ), проверка `finish` с подменой модели — входы 03 (4838 знаков) и 09 (27245) те же.
- **Серия.** Писатель `plain27t` (27B NT, T=0,6), 10 входов EV13 × seed 1, 2 = 20 сессий, по одной (`runs/evw_1113/run.sh`,
  логи `runs/evw_1113/logs/<вход>_ev_s<seed>.jsonl`). База без оценщика — сессии `plain27t` s1 EV13 (00, 03, 04, 14) и
  11.11 (01, t4); пар нет: другой промпт разводит сессии с первого хода.
- **Мерка.** Глазами по diff против входа: точна ли итоговая правка (как в разметке EV13). Рядом: сколько раз finish,
  вердикты по кругам, верен ли каждый вердикт оценщика (моя разметка), что писатель сделал с ответом Failed — правил
  указанное место, подгонял под оценщика или спорил.
- **Ожидание (13.11, 20:47 по `date`, до запуска).**
  - Итоговая правка точна чаще базы: в EV13 из 4 правок 27B без оценщика 3 Failed (00, 04, 14), оценщик их ловил
    (04, 14 — верно; 00 — EV6a верно по вердикту, довод другой). Жду по 00, 04, 14 хотя бы одну исправленную по ответу.
  - Риск 1: ложное Failed верной правки (в EV13 — 03 у EV6a, 09 у EV12) → писатель портит верную правку или тратит круги.
  - Риск 2: писатель подгоняет под формулировку оценщика, а не под наблюдение (как под механическое Ok, writer.check.md).
  - Риск 3: правки промпта (05, t4, 14) — оценщик промпта на t4, 14 ставил Failed по делу; писатель, вероятно, уберёт
    детали задачи, но может уйти и от сути.
  - Время: сессия 8–17 мин без оценщика, вердикт 1–2 мин, круги — по 1–3; всего 5–7 ч.
- **Первый запуск оборван (13.11, 20:47–21:00).** 00 s1 кончилась по лимиту bash: писатель правил в финальных ходах и
  `finish` не вызвал — оценщик не сработал ни разу. Правка при этом из тех, что оценщик должен ловить (`cycling` ищет
  период 1 и 2, а наблюдение — про круг из трёх). Поправка 084c1b7: когда финальные ходы кончились, а Ok оценщика нет,
  правка идёт к нему сама; Ok — конец, иначе писатель получает ответ («The turns ran out, so your change went to the
  reviewer…») и снова 3 хода без bash. Оборванное — в `runs/evw_1113/aborted_v1`; серия перезапущена с начала.
- **Второй запуск оборван (13.11, 21:01–21:30).** В 00 s1 писатель вызвал finish на последнем финальном ходу, получил
  Failed, и тут же, по концу ходов, та же неизменённая правка ушла к оценщику второй раз — лишний вызов и лишние 3 хода.
  Поправка (ветка, следующий коммит после 084c1b7): правка, не изменённая с последнего вердикта, повторно не оценивается —
  конец как есть (и на finish, и по концу ходов). Первый вердикт по делу: «run 4, model call 20: … crashed with an
  `AttributeError` because `call_hook` was passed a tuple of types `(Block, Steps)`» и ложное срабатывание новой проверки в
  удачном run 2. Оборванное — `runs/evw_1113/aborted_v2`; серия перезапущена с начала.
