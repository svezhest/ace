# EV4 — оценщик 27B NT: починенная подача шагов и случайный порядок задетых прогонов

[Указатель проб](../INDEX.md) · хронология: [13.11](../days/1113.md) · план: [EV](../1112/EV-evaluator-plan.md) ·
прежняя проба: [EV3-t1](../1112/EV3-t1-27b.md)

- **Повод.** Вопрос автора «как поднять пользу оценщика 27B NT». Ответ автора на предложения: «починить подачу
  естественно», «порядок можно и случайный»; голосование и агентный режим — «не варик», дорого («оценщика хотим
  дешёвым — он же будет в цикле писателя»).
- **Гипотеза.** Единственная ложная браковка NT (c6957a) — от дефекта входа: `tests/runs.py steps` показывает код шага
  только первой строкой, и чередование A, B, A, B в run 16 выглядит как одиночный повтор. Код целиком её снимает.
  Случайный порядок задетых прогонов (сейчас run 1 из наблюдения всегда первым) может ослабить якорь на run 1 — все
  ложные «Ok» NT решены по run 1.
- **Что поменялось во входе** (коммит с этой записью; `probes/1112/ev_input.py`, флаги `--full-steps`, `--shuffle`):
  - Шаги перед местом расхождения рисует сам вход (`steps_full`), а не `runs.py steps`. Писательский `runs.py` не
    тронут. Код каждого шага целиком (до 30 строк по 200 знаков) и до 4 строк ответа среды без строк с тремя
    обратными кавычками. Заголовок прогона говорит прямо: модель видит иное на вызове K, значит, харнесс поступает
    иначе сразу после вызова K−1, последнего шага в списке. Это снимает и путаницу строки отчёта, где «model call K»
    показывает код ответа K−1 (EV3-t1).
  - `--shuffle 1`: строки задетых прогонов в отчёте перепрогона (внутри своего раздела) и разделы шагов идут в
    случайном порядке; зерно = `1:<state>`, у каждой правки свой порядок. Ссылки «The same as run 1» в отчёте
    остаются как есть и могут указывать вперёд.
  - Промпт, модель, профиль (`stands/plain27.json`, T=0), число вызовов — прежние. Вход длиннее: c6957a 7,3 → 9,6 тыс.
    знаков.
- **Две перемены сразу** (код целиком и порядок) — сознательно, ради одного прогона: обе — транспорт. Если результат
  разойдётся с ожиданием, разделю.
- **Набор.** 21 правка входа № 1, где механика по всем удачным прогонам полного вида говорит «Ok»
  (`runs/ev_1112/t1_mechok_items.json`, поле `blind` — слепая разметка). Плохих 11, верных 10. Было (EV3-t1): NT
  ловит 4 из 11, бракует 1 из 10 (c6957a); T — 7 и 0.
- **Ожидание (13.11, 01:20 по `date`, до запуска).** c6957a → «Ok». Остальные верные 9 из 9 «Ok», как были. Плохих
  поймано 4–5: порядок для якоря слабее формы ответа, большого сдвига не жду. Если поймано меньше 4 — подача
  мешает.
- **Запуск.** `python3 probes/1112/ev_judge.py runs/ev_1112/t1_mechok_items.json --stand plain27 --full-steps
  --shuffle 1 --out runs/ev_1112/t1_plain27_full_sh1.jsonl --work <копия писателя с полными логами app_r1>`; входы —
  `runs/ev_1112/inputs_full_sh1/`.
