# EV5 — оценщик 27B NT: свой блок на каждый задетый прогон

[Указатель проб](../INDEX.md) · хронология: [13.11](../days/1113.md) · прежняя проба: [EV4](EV4-nt-input-fix.md)

- **Повод.** Ревью входа сабагентом на Opus (13.11, только чтение, без прогонов). Отчёт `rerun.py` склеивает прогоны
  с похожим действием харнесса строкой «The same as run N». У склеенного прогона нет ни своего кода, ни своего
  сообщения. В 5f8c67, 75e00c, f0bed9, fa3135, 3d0bad решающий run 18 сведён к «The same as run 14», в 342a98 run 17
  записан «The same as run 1», то есть «как проблема». Вызов «model call K» в строке отчёта показывает код ответа K−1.
  Деление на passed / failed читается как «безопасно»: в рассуждении T по f0bed9 дословно «But all divergent runs are
  failed runs». Продолжение лога после места известно, слепая разметка держится на нём («перечитал — и пошёл
  дальше»), а во входе его нет. Автор на предложение: «да делай уже».
- **Гипотеза.** Ложные «Ok» NT отчасти от подачи: прогон, где правка ломает нормальный шаг, во входе обезличен. Свой
  блок на прогон с кодом и продолжением лога даёт NT увидеть такой шаг как нормальный.
- **Что поменялось** (`probes/1112/ev_input.py`, `run_blocks`, флаг `--blocks`; разделы «Replay» и «steps» прежнего
  входа заменены одним):
  - Сводка: сколько прогонов идут иначе (номера), сколько как в логе; что после места известно только из лога.
  - На каждый задетый прогон, по номерам: «### Run N (in the log the task was solved / failed)»; «The edited harness
    acts differently right after model call K−1.» и предложение самого `rerun.py` (`event_text` без склейки — тот же
    текст, что видит писатель у первого прогона группы); шаги лога K−6…K−1 с кодом целиком (последний — тот, с
    которым харнесс поступает иначе); шаги K…K+2 «with the original harness».
  - Без деления на разделы passed / failed — признак остаётся в заголовке прогона. Без перемешивания (EV4: прироста
    не дал).
  - Промпт, модель, профиль (`plain27`, T=0), один вызов — прежние. Наблюдение, diff, ряд версий, таблица прогонов —
    прежние.
- **Цена.** Вход на 21 правке: 13–45 тыс. знаков, медиана 22 тыс. (EV4 — около 9–10 тыс.). Больше всего добавляют
  шаги после места и код целиком у длинных шагов.
- **Набор.** Те же 21 правка (`runs/ev_1112/t1_mechok_items.json`). Было: EV3 — плохих 4 из 11, ложных «Failed» 1
  из 10; EV4 — 4 и 2.
- **Ожидание (13.11, 02:52 по `date`, до запуска).** Плохих поймано 5–7 из 11: прибавка в первую очередь на правках с
  run 18 (5f8c67, 75e00c, f0bed9, fa3135, 3d0bad), где у прогона впервые свой блок. Ложных «Failed» не больше 2 из
  10. Если плохих меньше 5 — дело не в подаче, следующая ступень — форма ответа по прогонам.
- **Запуск.** `python3 probes/1112/ev_judge.py runs/ev_1112/t1_mechok_items.json --stand plain27 --blocks --out
  runs/ev_1112/t1_plain27_blocks.jsonl --work <копия писателя с полными логами app_r1>`; входы —
  `runs/ev_1112/inputs_blocks/`.
