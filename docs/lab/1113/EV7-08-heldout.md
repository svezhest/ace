- **Зачем.** Подачу и форму ответа я подбирал на одних и тех же 21 правке входа № 1 (AppWorld, цикл в run 1). Чтобы
  не принять подгонку под этот набор за прирост, лучший вариант проверяю на входе 08: другой бенч, другая проблема
  (чередование «examine dresser 1» / «examine desklamp 1» в run 40), другие писатели (9B T, 9B NT, 27B NT, ручные o08).
- **Набор** (`runs/ev_1112/08_mechok_items.json`). Из 58 правок набора EV1-08 механика по всем удачным прогонам
  полного вида alf_r1 (40 прогонов) говорит «Ok» на 19: меняют run 40, удачные не трогают, не падают. Классы по моей
  разметке: A 15, M 3, спорная 1.
- **Слепая разметка (13.11, 03:42 по `date`).** Независимый агент, без моих меток, по тем же блочным входам
  (`--blocks`, кэш `inputs_blocks/`) и с доступом к полным логам. Ключ — `08_blind_key.json`, метки —
  `08_blind_labels.json` (178 тыс. токенов). Итог: 15 Ok, 4 Failed, 0 unclear.
  - Failed: E02 и E17 (мои M) — подсказка за 1–2 шага до лимита во всех прогонах, упёршихся в лимит, в том числе в
    run 24, где модель методично открывает новые шкафы. E11 и E13 (мои A) — проверка чередования сравнивает только
    действия 0, 2, 4 и срабатывает в run 1 (call 29) на повторе «take pan 1 from diningtable 1» с разными ответами
    среды; на call 33 модель сковороду берёт.
  - Расхождения с моей разметкой — 3 из 19: E11, E13 (мои A → Failed), E14 (моя M → Ok: харнесс завершает эпизод
    после трёх одинаковых пар; агент сам называет решение спорным).
  - Плохих в наборе мало (4 из 19): набор больше меряет ложные «Failed», чем пойманные.
- **Что мерю (запуск после EV6, 13.11, 05:15 по `date`).** На 19 правках 08, один ответ при T=0:
  1. NT v1 с прежней подачей (база, как EV3);
  2. NT v1 с блоками (как EV5b);
  3. NT, блоки и строка на прогон (как EV6a, лучший на t1).
  Затем T: блоки и строка на прогон на 21 правке t1 («опора, не клетка» — проверка, что сильной модели не хуже,
  чем с v1: 17 из 21), и на 08 — v1 и блоки со строкой на прогон.
- **Ожидание (05:15, до запуска).**
  - NT v1, прежняя подача: плохих 1–2 из 4, ложных «Failed» 0–2 из 15. Прежний отчёт склеивает прогоны, плохие
    E11/E13 решаются по run 1, тонкое место.
  - NT, блоки и строка на прогон: плохих 2–4, ложных 1–3. Риск: в ALFWorld несколько циклов в разных прогонах (16,
    36, 11), и строка на прогон может назвать часть из них нормальными шагами, как run 9 на t1.
  - Если у варианта 3 верных меньше, чем у базы, прирост на t1 — подгонка под набор.
  - T, блоки и строка на прогон на t1: верных не меньше 16 из 21 (с v1 — 17).
