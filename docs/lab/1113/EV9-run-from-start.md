# EV9 — оценщик: в блоке прогона — весь прогон до окна, по строке на шаг

[Указатель проб](../INDEX.md) · хронология: [13.11](../days/1113.md) · прежняя проба: [EV8](EV8-earlier-same-step.md)

- **Повод.** EV8 отвергнута: строка «тот же код раньше на вызовах …» — отбор шагов по признаку повтора, то есть
  наводка на цикл (автор: «действительно наводка на цикл, датасет у нас конечно перекошен»; «не повтором единым»).
  Но корень ложных «Failed» на run 9 t1 остаётся: окно в 6 шагов прячет начало прогона. В логе run 9 прежний харнесс
  на вызове 12 не исполнил код («You sent the same code as in the previous step…»), и модель начала задачу заново:
  вызовы 13–19 повторяют 1–9.
- **Гипотеза.** Оценщику не хватает прогона целиком, а не факта о повторе. Если показать весь прогон до окна без
  отбора — по строке на шаг, — суждение о шаге опирается на ход прогона, а не на 6 шагов.
- **Что поменялось** (`ev_input.render_brief`, `run_blocks(brief=True)`, `ev_judge.py --brief`). В блоке прогона перед
  окном: «The log from the start of the run, model calls 1-(K−7), one line per call (the code on one line, and the
  first line of what came back):» и строки «model call j: <код в одну строку, ≤160 знаков> → got: <первая строка
  ответа, ≤100>» (или «→ the harness did not run it and said: …»). Строки «Earlier in this run…» (EV8) нет. Остальное —
  как EV6a: блоки, промпт `runs`, `plain27`, T=0.
- **Набор.** t1 (21) и 08 (19), слепая разметка. Сравнение — с EV6a/EV7: t1 18, 08 18, всего 36; ложных «Failed» 2 из
  25, пойманных 13 из 15.
- **Оговорка о шуме.** Автор: раз NT на тех же входах не хуже T, то разница между вариантами в 1–3 правки из 40 — шум,
  а не прирост. Засчитываю только сдвиг, который виден в обоснованиях (какое место и почему названо), а не в счёте.
