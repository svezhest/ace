# EV21 — писатель: finish → check, пример хода, лимит не печатается

[Указатель проб](../INDEX.md) · тема: [оценщик](../../writer.evaluator.md), [лимит bash](../../writer.bash-limit.md) · прежние: [EV15](../1113/EV15-writer-with-evaluator.md), [EV16](../1114/EV16-no-printed-limit.md)

- **Повод.** Автор (15.11): «bash limit 25 это явно какое-то недоразумение… почему модель так поздно отсылает? может надо
  дать понять модели что это некая check функция для ее решения. показать в примерах». Потом: «finish -> check и пример
  хода и не печатать лимит, и везде большой лимит. кстати, не печатать лимит надо бы везде».
- **Пробовали ли.** Лимит не назван — EV16: первый finish не раньше (медиана 27 bash), часть сессий читает до контекста.
  finish как проверку и пример хода в промпте писателя не пробовали. P3 (3.11): правка без проверки не применяется — это
  запрет, а не цель, и проверкой тогда был smoke.
- **Корень, как я его вижу.** finish описан как «сдай, когда готово», то есть это конец работы. Звать его рано незачем,
  что с числом в промпте, что без него.
- **Что поменялось** (ветка `feature/writer-check`, 422aa93, от develop c732b26 + поправки EV16 7b7d7e8, 21dd679):
  - инструмент `check()` вместо `finish()`: «This is how you test a change: call check as soon as you have one, and
    again after each fix. If the reviewer answers Ok, the session ends with your change…». Конец без Ok — check без
    изменений в src/ (как было у finish);
  - в промпте раздел «# Example»: ход на чужом харнессе (обрезка вывода без пометки — такой проблемы в наших входах нет):
    grep → edit → check → Failed с местом → sed → edit → check → Ok;
  - лимит bash писателю не называется (BASH_LIMIT 100, STEP_BUDGET 200 — предохранители), размер обрезки вывода не
    называется («Long output is truncated»); финальные ходы с 40 тыс. токенов, вердикт и при обрыве по контексту
    (EV16); предохранитель числа вердиктов 6 → 30, не печатается.
  - Сообщения в момент наступления предела («You have used all … bash calls») остаются: это не предупреждение заранее.
- **Отдельно, не меряется здесь:** ветка `feature/no-printed-limits` (22eb845) — то же для ревьювера: бюджет вызовов
  из промпта, «N of M bash calls left», счётчик контекста, «{left} tool calls left», размер обрезки.
- **Серия.** 27B `plain27t`, оценщик `plain27`; 10 входов EV15 × seed 1, 2; теги `<вход>_ck_s<seed>`
  (`runs/evw_1113/run_ck.sh`). Пар с EV15 нет.
- **Мерка.** bash до первого check; число check в сессии; что писатель делает после Failed (читает названное место или
  правит вслепую); итог — глазами по diff против входа (правило автора 14.11: пример из случая задачи — законно).
  База — EV15: первый finish ≈ 25 bash, итог Ok 10 / спорно 3 / F 6 из 19.
- **Ожидание (15.11, 05:05 по `date`, до запуска).** Медиана bash до первого check < 15. Check в сессии ≥ 2 у большинства.
  После Failed писатель читает названное место. Итог не хуже EV15: Ok ≥ 10 из 20. Риски: писатель зовёт check после
  одного bash, не читая (как в примере), и подгоняет правку под ответы оценщика. Сессии дольше: каждый check — перепрогон
  и вызов 27B. Пример могут копировать (обрезка вывода не к месту).
