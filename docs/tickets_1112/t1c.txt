## Observation (problem)
run_1 fails as "step limit". After a KeyError (line 57) the model starts alternating two steps: messages 61, 67, 73 are byte-identical (`print(recommendations[0]["album_id"])`), and 64, 70, 76 are the same `show_album` call. This goes on until line 172. The harness has a repeat guard, but it only compares the new code with the previous step (src/harness.py:95-99), so an A, B, A, B pattern is never detected. The guard should look at the last few steps, not only the last one.

- logs/run_1.jsonl:61,67,73 identical `print(recommendations[0]["album_id"])`

- logs/run_1.jsonl:175 'bridge end', reason 'step limit'
