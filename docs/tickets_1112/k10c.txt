Observation from a study of the agent's failed runs (references to logs/ point to the runs in logs/):

## Observation (problem)
The `stalled()` guard only detects a stall when the last 3 actions were empty/no-op strings. It cannot detect a model that is stuck on a wrong line of reasoning but keeps issuing DIFFERENT valid actions that change the room/observation.

Evidence: Run 32 — the model went in circles reasoning about a "hot mug" task, repeatedly planning to `examine stoveburner 1`, which produced the identical observation twice in a row ("On the stoveburner 1, you see a pot 1..."), then the episode ended with `{"reason": "error", "status": "agent invalid action", "detail": "repeated action"}` (bridge.py guard, REPEATS=3). The harness never told it to stop; it burned ~41 turns. The model's reasoning was captured in its long assistant content (2077 and 2339 chars) showing it went in circles about coffeemachine/microwave/pot.

Root cause: harness.py `stalled()` (lines 64-68) keys only on repeated empty actions, so a reasoning loop that still takes valid (non-empty) actions is never caught and runs to the guard or step limit.
