## Коротко

- **Проверка правки по тикету (TK\*).** После каждой правки писателя харнесс сам проверяет, изменился ли прогон из наблюдения, и прикладывает факты: какое условие мёртвое, значения операндов, перекрытый def. Девять вариантов, по 10–30 сессий. Механизмы фактов почти не меняют вердикты. Из 38 пар, разошедшихся из-за механизма, 35 с тем же вердиктом, 3 лучше, 1 хуже (мой брак).
- **TKK — вторая половина тикета:** удачный прогон, который должен остаться как в логе.
  - Итог 8 V / 3 P / 5 B / 14 x против 5/4/4/17 у TKD. Это намёк в плюс, около 1,8 SE.
  - Процесс сильнее: «keep Failed» разобран в 9 сессиях из 9. В 6 правку сузили, две из них дали V.
  - Это первый факт о том, «что должно остаться», который писатель реально берёт.
- **Сверка промпта и логики на изъяны вида «двойная проверка».** Нашлись три:
  - конец bash остался от мира без авто-проверки;
  - `--at` писатель находит, только читая исходник мерки;
  - README и комментарии узлов дерева врут, а промпт велит на них опираться.

  Под это собрана чистая база PL: голые виды и `--clean`, 30 сессий в очереди.
- **Голые виды (решение автора).** Из `src/*.py` убраны комментарии и докстринги. README минимальный: где src, где logs, формат. Поведение то же: все записанные прогоны на голом src идут «no changes». В дереве так же чистится каждый узел перед замером.
- **Повтор команды.**
  - Ответ «This is the same command as tool call N» — странный факт без «что делать» (автор).
  - Из 86 повторов 50 идут после ошибки, 10 — после пустого вывода.
  - По литературе (arXiv 2608.23651) повтор тянет дословная копия вызова в контексте, а «do not repeat» не работает.
  - Офлайн-проба на 48 точках сравнивает: ответ как есть; ответ с «нового не будет»; пересэмпл без дубля; вырезание копий с пересказом команды чистым вызовом 9B.
  - В очереди около 1360 вызовов, итогов на момент записи нет.
