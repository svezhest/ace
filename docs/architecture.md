# Архитектура стенда

Метод — ученик (`Learner`), собранный из уровней. Цикл (`ace/loop.py`) один на все методы: он гоняет
задачи, попытки и протокол и зовёт хуки ученика на своих масштабах. Уровни заменяются по одному; стык с
проверкой один — память и извлечение.

## Уровни

| уровень | что решает | интерфейс | где |
|---|---|---|---|
| мета | учится ли сам ученик: навык, откат к лучшей версии | обёртка над `Learner` | `Meta`, `Gate` (позже) |
| попытки | сколько попыток и чем они различаются | `Attempts(n, temperature(k))` | `loop.py` |
| в зачёт | чей ответ считается | `Attempts.pick`: `first` / `greedy` / `vote` / `best` (pass@k) | `loop.py` |
| вердикт попытки | что обучение знает о правильности попытки | `golden` / `yes_no` / `judge` / `none` | `verdict.py` |
| вердикт группы | что известно о группе целиком | `vote` / `none` | `verdict.py` |
| извлечение | что вынести из группы попыток | `Extractor(ex, group, memory) -> Extraction`, `gives` | `extract/` |
| память | как вынесенное входит в память, что в ней живёт | контейнер + `learn(ex, extractions)`, `requires` | `memory/`, методы |
| показ | что из памяти видит решатель и когда | `Show.prompt(...) -> Prompt`, `Show.on_step(...) -> Patch` | `show.py` |
| когда учится | раз в сколько вопросов память принимает извлечённое | `every`, `flush` | `Learner` |

Источники различия попыток: температура (`Attempts.temperature(k)`), выборка показа и разделённая память
(показ получает номер попытки `k`), заметка рефлектора (извлечение вызывает `ex.retry(память, заметка)` —
новая попытка того же вопроса; это стрелка извлечение -> попытки, раунды ACE).

## Масштабы и хуки

Масштабы не смешиваются: у каждого свой объект, свой хук и свои вердикты.

| масштаб | объект | хук ученика | при обучении | на val и тесте |
|---|---|---|---|---|
| шаг | `Step(tool, args, result)` внутри `Attempt` | `on_step(ex, attempt, step) -> Patch \| None` | да | да (только показ) |
| попытка | `Episode` | `prompt(ex, item, k) -> Prompt` до, `on_attempt(ex, episode)` после | да | только `prompt` |
| вопрос | `Group` (есть всегда, обычно из одной попытки) | `on_question(ex, group)` | да | нет |
| батч | список `Group` | `on_batch(ex, groups)` раз в `every`; неполный в конце прохода — если `flush` | да | нет |
| проход | — | `on_pass(ex)`; `ex.evaluate()` — точность на val | да | нет |

`ex` — эксперимент: модель, задача, номер вопроса, флаг `training`, `evaluate()`, `retry()`.

## Объекты цикла

- `Prompt(system, tools, deps, rounds, shown, temperature, note)` — что ученик даёт попытке: добавку к
  системному промпту решателя (роль задачи и подсказку среды ставит цикл), инструменты чтения памяти,
  id показанного, температуру, заметку к сообщению.
- `Attempt` — идущая попытка: вопрос, `k`, `training`, шаги, `Patch`-и, исходы показа (`fired`).
- `Episode` — законченная попытка, как её видит обучение: траектория, ответ, шаги, `used` (что решатель
  прочёл инструментами — пишет цикл), `ok` и `target` от вердикта. Верный ответ лежит в эпизоде только при
  `golden`; при `yes_no` только `ok`, при `none` ничего.
- `Group` — попытки одного вопроса: `episodes`, ответ в зачёт и как он выбран, `vote` (вердикт группы),
  `target` (только при `golden`). Контраст попыток — не вердикт, а извлечение (TF-GRPO).
- `Patch` (`model.py`) — вмешательство посреди попытки, единственное: `system` переписывает системный промпт
  (SCOPE, как в апстриме), `append` дописывает сообщение в конец истории, `tool_result` дописывает к
  результату инструмента (наши хуки: урок после ошибки). Префикс истории при `append` цел.

## Стык требований

Память объявляет, какие добавки ей нужны от извлечения (`requires`), извлечение — какие даёт (`gives`).
Имена добавок — в `ace/extract/__init__.py`: `labels` (метки записей helpful / harmful), `confidence`,
`domain`, `attribution`, `ig`, `best_answer`. Ядро (`lessons` — текст уроков, `scores` — баллы попыток)
есть всегда. `Learner` при сборке сравнивает два множества; нехватка — ошибка сборки с именами добавок.
Остальные согласования (показ читает счётчики и т.п.) держат трасса промптов и тесты-мостик.

## Два мира памяти

- **Уроки** (`memory/lessons.py`): запись = неизменяемый текст + статистика. Правка — операции
  `ADD` / `UPDATE` / `DELETE`, их применяет код; `UPDATE` = новая запись на месте старой с новым id и нулевой
  статистикой. Счётчики — свёртки журнала исходов записи; оценка при рождении (confidence, ig) — поле
  записи метода. Разрешённые модели операции — флаги контейнера. Контейнеры: `Lessons` (список), `Sections`
  (разделы с общей нумерацией). Отсев — `prune(условие)`.
- **Документы** (`memory/documents.py`): `Document` — один текст целиком (DC), `Files` — файлы и папки,
  правка инструментами `fs.py` (MCE). Статистики нет, учёт — по версии памяти (мета).
- Смесь запрещена: файловых инструментов над уроками со счётчиками нет. Каталог записей с `read` — это
  показ, только чтение.

## Сборка метода и абляция

```python
ace = Learner("ace", memory=Playbook(curate_ops), extract=Reflector())
ace_text = swap(ace, "ace_text", extract=Reflector(free=True), memory=Playbook(curate_ops, prune=None))
```

Абляция — замена одного уровня через `swap` (`dataclasses.replace`, проверки сборки идут заново). Если
замена ломает стык, сборка падает: `swap(ace, extract=Reflector(free=True))` — «память требует labels,
извлечение их не даёт»; значит, ступень меняет и память (без меток нечего считать и отсеивать).
Метод со своей логикой на масштабе переопределяет хук в подклассе `Learner` (SCOPE учится на шаге);
остальное берёт от уровней. Библиотека не знает конкретных методов: веса, разделы, триггеры — у методов.

## Протокол

- Онлайн: поток задач, память учится по ходу, `epochs` проходов, в зачёт последний.
- Офлайн: обучение на train, после прохода val; лучшая по val версия (строго больше, при равенстве ранняя)
  снимается `learner.snapshot()` и на тесте возвращается `restore()`. Выбор версии — протокол цикла.
- `training = False` на val и тесте: цикл зовёт только `prompt` и `on_step`; учиться на шаге ученик сам не
  должен (`attempt.training`).
- Кэш val — по `learner.key()` (содержимое памяти); при случайном показе (`show.random`) ключа нет и val не
  кэшируется.
- Лог по вопросу: группа (ответы, вердикты, температуры, показанное, прочитанное, `fired`, `Patch`-и),
  ответ в зачёт и способ выбора (`pass@k` помечен), решения Gate на этом вопросе.

## Обёртки (интерфейс ученика для них)

- `Hooks(ученик)` — хуки по ошибкам = извлечение (урок по ошибке с триггером) + память (уроки со счётчиками
  исходов показа) + показ после ошибки (`Patch(append)` по триггеру). Ему нужны шаги попытки
  (`attempt.steps`) и исходы показа (`attempt.fired`), остальные хуки делегируются ученику.
- `Gate(ученик)` — на батче: `snapshot()`, `on_batch` ученика, val до и после, `restore()` при ухудшении;
  решения — в `learner.gated` (в лог по вопросу).
- `Meta(ученик)` — MCE: мета-агент пишет навык в `learner.skill` (текст, который ученик подставляет в свои
  промпты обучения; у базового агента MCE — инструкция правки файлов), история версий через
  `snapshot()` / `restore()` и `ex.evaluate()`; откат к лучшей по val на проходе.
