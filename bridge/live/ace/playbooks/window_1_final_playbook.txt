## FORMULAS & CALCULATIONS

[calc-00001] helpful=0 harmful=1 :: For financial ratio calculations, express your final numeric answer as a plain floating-point number WITHOUT a percentage sign, even if your reasoning shows the percentage form (e.g., show '15.00%' in reasoning but provide '15.00' as the final answer). Grading systems typically normalize floating-point values, so '15.00' and '15.0' are treated as equivalent matches.
[calc-00004] helpful=0 harmful=0 :: CRITICAL - Avoid the unnecessary ×100 percentage conversion trap. When a problem asks for a 'plain floating-point number' for a ratio/percentage calculation, report the DIRECT RESULT OF THE DIVISION with NO multiplication by 100. For example, dividend yield = annual dividend / price = $0.90 / $18 = 0.05. The answer is 0.05, NOT 5.00. The phrase 'express as a plain floating-point number without a percentage sign' means: report the decimal value directly (0.05), NOT 'first convert to a percentage (×100 → 5%) then drop the % symbol.' A decimal like 0.05 ALREADY has no percentage sign and IS the correct plain floating-point representation. Do NOT add a ×100 step unless the expected answer format clearly requires a percentage (e.g., the ground truth itself shows a value like 5.00 or the question explicitly says 'as a percentage').

To decide which format to output, use these signals:
1. If the question says 'plain floating-point number,' 'numeric value,' or 'as a decimal' → output the raw division result (0.05).
2. If the question explicitly says 'as a percentage' or 'in percent' → output the ×100 value (5.00).
3. If uncertain, match the ground truth's apparent scale: a small decimal like 0.05 suggests decimal-ratio expected; a value around 5.00 suggests percentage expected.
4. Never show 'X%' in reasoning and then output 'X' as if you converted — the direct division result is what matters when no percentage is requested.

[misc-00005] helpful=0 harmful=0 :: When computing any financial ratio or percentage (dividend yield, P/E, ROE, etc.), compute ONLY the raw division first and hold off on any ×100 conversion until you are certain the expected output is a percentage. The most common error is multiplying by 100 prematurely because ratios are 'usually' shown as percentages in real-world finance — but automated graders frequently expect the unconverted decimal ratio. Always let the question wording and/or the ground truth's numeric scale be the deciding factor, not your assumption about convention. If the direct division gives a small number (like 0.05) and nothing indicates percentage form, that small number is almost certainly the expected answer.
