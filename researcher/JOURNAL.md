### Что оставлено и почему
`--policy compact` (теперь по умолчанию): при оценке ≥ 45K модель пишет сводку (те же tools, `tool_choice: none`,
при пустом ответе — вторая просьба), всё до хода 5-го с конца вывода заменяется user-сообщением «сводка + список
записанных report»; WARN выключен, HARD 58K. Почему:
1. Порог 45K вместо 30K: за 100 вызовов ALFWorld-сессия доходит до 28–45K, и потери чаще всего не случается вовсе
   (S2, S9) или случается один раз. base теряет чтение в середине сессии (вызов 26–40), как раз перед report.
2. Когда потеря случается, сводка модели держит факты с номерами строк (S5: MAX_STEPS:27, calls[0]:110, run_15:11–12),
   а модель перечитывает нужное (S4). edge (только у края) за 100 вызовов не срабатывал вовсе — как политика он
   здесь не отличим от «ничего не чистить»; compact = edge + сводка на случай, если край достигнут.
3. notes модель использует поздно, как сводку перед report (S3: 2 заметки на 97 вызовов), и они не спасли от
   потерянной поправки.
Что из этого загрязнено: «report стали вернее» (compact S5/S9: по 4 верных по сути против 1–2 у base S6/S10) —
суждение по трассам, которые я читал; на E (S7/S8) я не настраивал, но S8 фактически шла с откатом на заглушки.

### 7.1 Механика (fsr.py; по умолчанию поведение прежнее — проверено: `--dry` без новых ключей даёт тот же промпт)
- `BASH_LIMIT` (None = нет): считаются все вызовы bash в основной фазе, включая повторы и отказы песочницы. Вызовы
  bash сверх лимита в том же ответе не исполняются («all N bash calls are used; this command was not run…»); в конце
  хода — `enter_final("bash limit")`. Сообщение перехода — то же общее, что у бюджета вызовов: «You have used all N bash
  calls. bash is no longer available. Record each finding you can support with report now (several report calls in one
  reply are fine), then call finish. Example: …». Инструменты финала — report и finish (как было).
- Строка промпта о конце сессии при `BASH_LIMIT` честно называет лимит: вместо «the session ends after STEP_BUDGET tool
  calls» — «bash can be called N times; after that only report and finish remain, for a few turns, and the session
  ends». Это описание механизма, не правка под ошибки трасс; больше промпт не менялся.
- `FINAL_FIX_TURNS` (0 = как раньше; в сессиях 2): после отклонённого в финале report ходы финала не расходуют
  FINAL_TURNS, пока «долг» не закрыт — до хода, где есть принятый report и нет отказов (не больше FINAL_FIX_TURNS
  таких ходов; v2, см. 7.2 — в v1 бесплатен был только сам ход отказа); finish при открытом долге откладывается
  («Not finished yet: a report call was not recorded (the reason is in its result). Fix it and call report again, then
  call finish.»). Причина отказа модель видит, как и раньше. Итого финал ≤ FINAL_TURNS + FINAL_FIX_TURNS = 4 + 2 ходов.
- Счётчики в `end.stats`: `bash_calls`, `bash_over_limit`, `final_rejected`, `final_fix_used`, `finish_deferred`; в meta
  `limits.bash_limit`, `limits.final_fix_turns`. Проверено на заглушке модели (`scratchpad/a1/mock_a1.py`: повтор
  считается, 4-й вызов при лимите 3 не исполнен, отложенный finish, 2 бесплатных хода, затем принятый report).
- Остальное — как A3: `--policy compact --set STEP_BUDGET=300 --set STEP_WARN=285 --set CLEAR_AT=55000`, T=0.6, seed
  модели — как у A3-сессии того же набора. Правки 5.4 (качество сводки, серии повторов) не делались.
- Запуск: `scratchpad/a1/launch.sh VIEW RUNS SEED LIMIT TAG K`; логи `logs/r<runs>_compact_s<seed>_a1<…>.jsonl`.

## 8. A7 — форма evidence (29.10)
Вопрос: строгие ссылки `path:line` с проверкой харнессом (strict, как в A1) против свободной формы (free: цитата/текст
с путём, без проверки номеров строк) — какая даёт больше верных и точных report при той же цене, и сколько вызовов
съедает охота за номерами строк. Всё прочее — как A1-40: `--policy compact --set STEP_BUDGET=300 --set STEP_WARN=285
--set CLEAR_AT=55000 --set BASH_LIMIT=40 --set FINAL_FIX_TURNS=2`, T=0.6, K=5 на обоих бенчмарках (раздела 6 к старту
10:20 и к концу 12:02 в журнале нет — K для AppWorld взят 5 по заданию).

### 8.1 Механика (fsr.py; по умолчанию поведение прежнее)
- `--set EVIDENCE_MODE='"free"'` (было поле без реализации). В free меняются **только описания evidence**: предложение
  об evidence в строке report системного промпта, описание поля evidence в схеме инструмента, пример report
  (`EX_EV_FREE = ["logs/run_N.jsonl: <short quote>", "src/FILE:12-30"]`) и подсказка при отказе. Строку промпта менял
  вместе со схемой, потому что она описывает тот же механизм (strict-текст «References are checked» при free был бы
  неправдой); остальной промпт, включая «Every finding must rest on lines…» и подсказку про jq («N is the line number to
  cite»), не трогал. Текст free: «evidence is a list of what supports the finding, in free form: a short quote copied
  from a file together with its path, "path:line" or "path:start-end", or a path alone, for example … Paths are checked
  to exist; line numbers and quotes are not checked.»
- Проверка free (`check_evidence_free`): непустой список строк; если элемент начинается с пути (`path`, `path:…`,
  `path: текст`; путь — есть `/` или расширение), путь должен существовать в виде; номера строк и текст не проверяются.
  Строковое evidence в free не режется по запятым (цитата цела).
- Проверено: `--dry` без нового ключа — байт в байт с копией до правки (`scratchpad/a7/fsr_before_a7.py`) на обоих

### 8.4 Находимы ли цитаты механически (для фазы B)
По 127 элементам evidence free-сессий (`ev.py`, все попытки):
- текст элемента целиком найден в файле — 28 (22%): дословные строки промпта/кода (`src/starting_prompt.md: 'Paginated
  APIs: Always process all results…'`, строки results.jsonl), иногда склейка соседних строк через «;»/«...» (находит
  только окно из нескольких строк);
- найден только фрагмент в кавычках — 47 (37%), чаще всего не однозначно: `'examine stoveburner 3'` — в 37 строках,
  `'The task has been completed successfully'` — в 31 строке run_37;
- не найдено ничего — 52 (41%): пересказ («src/hooks.py: (empty file - no hooks defined)», «… appears 44 times») и

  — такой фразы в run_33 нет);
- место определяется однозначно (одна строка или одно окно) — 45 элементов (35%).
Вывод для B: **по free-evidence место механически находится примерно в трети элементов**; подстрочный поиск по
пересказу не работает, а фрагменты-действия ALFWorld/код AppWorld повторяются по десяткам строк. Если редактору нужна
точка в файле, free без проверки её не даёт; strict даёт разбираемую ссылку всегда, но её содержимое тоже не проверено.
