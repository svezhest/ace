## 1. Бенч = оригинал + минимальные фикстуры (сделано)

Схема одна на оба бенча: **цикл эпизода — апстримный, без правок; харнесс — агент этого цикла; мост — транспорт.**
Мост передаёт ответ модели честно, лимит считает бенч (по ходам, которые до него дошли), отбивка хука до бенча не доходит
и хода не тратит.

**ALFWorld** (`alfworld/bench/`, коммит `e9a0022`)
- `agentbench_alfworld/` — файлы задачи ванильного AgentBench (THUDM, `d1e4a10`, задача из 5bf4eb2 «publish agentbench_fc»)
  без изменений; хэши в `UPSTREAM.md`, тест сверяет. Зависимость: `agentrl-worker==0.4.0` (Task, Session) в `.venv`.
- `fixture.py` — делает для одного эпизода то, что `TaskWorker` agentrl делает по HTTP (`start_sample`, `interact` через
  `session.controller.agent_pull`). Фикстуры: параметры задачи как в конфиге Harness-R1 (max_step 50, инструмент
  take_action), файл сплита на одну игру, `$ALFWORLD_DATA/logic` из пакета alfworld, строка лога задачи о повторах (→ detail).
- `src/bridge.py` — транспорт: `start()`, `send(reply)` → новые сообщения задачи, `finished`, `end`.
- `src/harness.py`: системный промпт задачи подменяется `src/starting_prompt.md`; сообщение задачи «нет вызова»
  («No executable tool calls found…») — на `src/no_tool_call.md` / `invalid_tool_call.md`; каждый ответ модели уходит
  задаче как есть; `block_and_prompt` — ответ задаче не уходит (хода нет). Убраны `rewrite_action` / `force_action`
  (это и была подмена ответа).
- Проверка: 38 логов `view/` прогнаны реплеем (`tools/replay.py`) через `view_v3/src` и задачу апстрима — **38/38 разговоров
  байт в байт, ok/reason те же**. Тесты 14/14.

**AppWorld** (коммит `bce6bdb`)
- Эпизод — собственный цикл AppWorld (`experiments/code/simplified/agent.py`: `Agent.solve_tasks` для одной задачи),
  харнесс — агент. Фикстура `HarnessAgent(Agent)` в `runner/env_server.py`: `next_execution_inputs_usage_and_status` отдаёт
  вывод харнессу и берёт его код; `log_usage` дополнительно запоминает `task_completed()` (ту же проверку цикл делает сразу
  после). Параметры — из конфига эксперимента (max_steps 50, appworld_config, лимиты usage). Цикл идёт в главном потоке
  (таймауты AppWorld — SIGALRM).
- Проверка: 20 логов `view/` реплеем — **20/20 байт в байт, ok/reason те же**; реплей апстримного прогона
  `ornith9b_react_dev` — как до переделки: запросы 56/57 (известное расхождение `50e1ac9_2`), оценка 57/57. Тесты 13/13.

**Общее**: живые логи-события в раннерах (`runner/events.py`): `bridge` (start/send/fill/execute с номером хода, `not_shown`
— сообщения бенча, которых нет в разговоре; `end`), `prompt`, `env`, `model`, `harness`. Проверка честности после эпизода:
всё, что ушло бенчу, — ответы модели по порядку (ALF — сообщение целиком; App — каждая строка кода есть в ответе); иначе
`harness error`. Клиент модели больше не считает ходы. Smoke редактора и копии тестов в `editor/` переведены.

## Вопросы к тебе
1. **Отбивка = бесплатные ходы.** Сейчас ограничены только стеной (3600 с на эпизод) и контекстом. Харнесс может
   отбивать бесконечно; ставить ли свой предел вызовов модели на эпизод (и какой), или так и оставить?
2. **ALFWorld: конец эпизода по лимиту игры.** Игра (TextWorld) сама закрывает эпизод на 50-м действии
   (`max_nb_steps_per_episode: 50` в конфиге alfworld), статус задачи тогда `completed`. Сначала мост писал это `finished` —
   ревьювер `final` прочитал как «задача выполнена, но засчитана как step limit» (ложный report на 4 прогонах). Исправил:
   фикстура считает действия, на лимите игры конец — `step limit` с detail «the game's limit of 50 actions»; логи v3
   переписаны (только событие end; реплей 38/38). Ветки ALF, шедшие на старой метке, отложены в `researcher/logs/aborted`.
   Следствие: в ALFWorld `finished` теперь совпадает с победой (24 из 24) — других концов у игры нет. Так нормально?
3. **Липкий статус задачи AgentBench.** После ответа без вызова задача ставит `agent validation failed` и не сбрасывает —
   даже если потом игра выиграна. Мост пишет `status` как есть рядом с `reason`. Оставить?
4. **AppWorld: лимиты usage.** В конфиге апстрима `max_output_tokens_per_task: 100000` — цикл закончил бы эпизод. Фикстура
   отдаёт пустой `Usage()` (как и старый раннер — лимит не действовал). Передавать ли реальные токены, чтобы лимит работал?
5. **`reason` в `results.jsonl`** по-прежнему смешивает оценку и конец эпизода (вопрос с прошлого раза).
6. **Версия alfworld.** Dockerfile апстрима ставит alfworld с коммита `a5d3476`, у нас пакет 0.4.2. Тексты среды совпали с
   прежними логами (и раньше — с трассами Harness-R1, `tools/replay_hr1.py`), но формально версия другая.
