## COMMON MISTAKES TO AVOID

[err-00001] helpful=0 harmful=0 :: MISTAKE: Treating 'TotalFairValue' tags as dollar amounts. In this taxonomy, 'TotalFairValue' tags (e.g., EquityInstrumentsOtherThanOptionsVestedInPeriodTotalFairValue) represent COUNTS OF SHARES, not dollar amounts. If the entity is a dollar amount (e.g., '$6.5 million of unrecognized compensation cost'), do NOT select a TotalFairValue tag. Always check the entity's data type first.
[err-00005] helpful=0 harmful=0 :: MISTAKE: When two DIFFERENT entities in a sentence share the SAME numeric value (e.g., both are $2.87), do NOT disambiguate tags by assuming one tag applies to one entity and another tag to the other based on arbitrary or assumed conventions. The error occurred because the model conflated a Rights exercise price ($2.87) with a private placement price ($2.87) and assigned the wrong tag to each. Always anchor each tag to the SPECIFIC entity occurrence it describes by reading the surrounding text, not by value alone. Verify each mapping against the actual semantic role of the entity in its sentence.
[err-00010] helpful=0 harmful=0 :: MISTAKE: Mapping cash/restricted-cash amounts to unrelated tags like LineOfCredit or debt instrument tags. When the entities are cash/restricted-cash amounts being excluded from reported balances, do NOT select a LineOfCredit or debt instrument tag. Always check the entity's data type first and select the closest semantically related tag from the provided list.

## CONTEXT CLUES & INDICATORS

[ctx-00002] helpful=1 harmful=0 :: CONTEXT CLUE: The phrase 'unrecognized compensation cost' (or 'compensation cost not yet recognized') is a direct textual match to the tag family EmployeeServiceShareBasedCompensationNonvestedAwardsTotalCompensationCostNotYetRecognized. When this exact phrase appears, prioritize the tag that literally contains 'TotalCompensationCostNotYetRecognized' over semantically similar alternatives like 'fair value of grants'.
[ctx-00006] helpful=0 harmful=2 :: CONTEXT CLUE: When multiple entities share the same numeric value, identify each entity's semantic role from its surrounding text before selecting a tag. For example, 'exercise price of the Rights to purchase common stock' describes a class-of-warrant/right exercise price (map to ClassOfWarrantOrRightExercisePriceOfWarrantsOrRights1), while 'price per share in a private placement' describes a sale-of-stock price (map to SaleOfStockPricePerShare). Even if both values are identical (e.g., both $2.87), they map to DIFFERENT tags because they describe different entities. Anchor each tag to the specific entity occurrence it describes, not to the value.
[ctx-00008] helpful=0 harmful=0 :: CONTEXT CLUE: Distinguish between the 'term of the award' (expiration period) and the 'vesting period' (requisite service period) — these are distinct concepts that must not be conflated. The 'term of the award' is the period during which the option/award is exercisable (e.g., 'The term of any stock option awards... is ten years' = ExpirationPeriod). The 'vesting period' is the requisite service period over which the award vests (e.g., 'amortized... over the requisite service period, which is generally the vesting period' = VestingPeriod). When text mentions 'years' in the context of the award's term or exercisability, map to ExpirationPeriod, NOT VestingPeriod. Only map to VestingPeriod when the text explicitly references the service period, vesting schedule, or requisite service over which the award vests.
[ctx-00009] helpful=0 harmful=0 :: When no exact tag exists in the provided list, select the closest semantically related tag. For example, if the entities are cash/restricted-cash amounts and no dedicated cash/restricted-cash tag exists, 'CashAndCashEquivalentsFairValueDisclosure' is the best available match. Always prioritize tags that are semantically related to the entity's nature over tags that are unrelated to the entity's nature.
## OTHERS
[misc-00003] helpful=1 harmful=2 :: DATA-TYPE-FIRST HEURISTIC: Before selecting any XBRL tag, determine the entity's data type: (1) dollar amount -> map to 'CompensationCost'/'Expense' tags; (2) share count -> map to 'TotalFairValue'/'NumberOfShares' tags; (3) time period -> map to 'PeriodForRecognition'/'VestingPeriod' tags. Never assume a dollar amount represents a 'fair value of grants' — verify the data type explicitly.
[misc-00004] helpful=0 harmful=2 :: TIME-PERIOD DISAMBIGUATION: For entities describing how long compensation cost will be recognized (e.g., '2.32 years' weighted-average recognition period), prefer the tag ending in 'PeriodForRecognition' (e.g., ...TotalCompensationCostNotYetRecognizedPeriodForRecognition1) over 'VestingPeriod' tags. 'VestingPeriod' describes the vesting schedule of awards, while 'PeriodForRecognition' describes the expense-recognition timeline — they are distinct concepts even if numerically similar.
[misc-00007] helpful=0 harmful=0 :: CASE-EXACTNESS HEURISTIC: XBRL tag names must be output with the EXACT case as specified in the ground truth, not assumed standard capitalization. The model failed by outputting 'ShareBased' (capital B) when ground truth is 'Sharebased' (lowercase b). Do NOT normalize or 'fix' the case of tag names based on convention or readability. Always copy the tag name verbatim from the ground truth or the provided tag list, preserving the exact capitalization of every word including prefixes like 'Sharebased', 'ShareBased', 'AwardVestingPeriod', etc. A case mismatch is a hard error even if the tag is semantically correct.
