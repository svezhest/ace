## COMMON MISTAKES TO AVOID

[err-00001] helpful=0 harmful=0 :: MISTAKE: Treating 'TotalFairValue' tags as dollar amounts. In this taxonomy, 'TotalFairValue' tags (e.g., EquityInstrumentsOtherThanOptionsVestedInPeriodTotalFairValue) represent COUNTS OF SHARES, not dollar amounts. If the entity is a dollar amount (e.g., '$6.5 million of unrecognized compensation cost'), do NOT select a TotalFairValue tag. Always check the entity's data type first.
[err-00005] helpful=1 harmful=0 :: MISTAKE: When two DIFFERENT entities in a sentence share the SAME numeric value (e.g., both are $2.87), do NOT disambiguate tags by assuming one tag applies to one entity and another tag to the other based on arbitrary or assumed conventions. The error occurred because the model conflated a Rights exercise price ($2.87) with a private placement price ($2.87) and assigned the wrong tag to each. Always anchor each tag to the SPECIFIC entity occurrence it describes by reading the surrounding text, not by value alone. Verify each mapping against the actual semantic role of the entity in its sentence.
[err-00010] helpful=0 harmful=2 :: MISTAKE: Mapping cash/restricted-cash amounts to unrelated tags like LineOfCredit or debt instrument tags. When the entities are cash/restricted-cash amounts being excluded from reported balances, do NOT select a LineOfCredit or debt instrument tag. Always check the entity's data type first and select the closest semantically related tag from the provided list.
[err-00012] helpful=0 harmful=2 :: MISTAKE: Selecting an unrelated tag when an exact match doesn't exist. When no exact XBRL tag exists in the provided list, do NOT select a tag that is only superficially related to the entity (e.g., based on shared keywords or numeric values). Instead, select the tag that best captures the core accounting concept of the entity, prioritizing semantic similarity. For example, a cumulative-effect adjustment to retained earnings should map to 'CumulativeEffectOfNewAccountingPrincipleInPeriodOfAdoption', not an unrelated tag that shares keywords. Always verify the semantic relationship between the entity and the selected tag before finalizing the mapping.
[err-00014] helpful=0 harmful=0 :: MISTAKE: Equating 'face value' with DebtInstrumentFaceAmount when the disclosure uses 'carried at' language. When a debt instrument is described as 'carried at its aggregate face value, less any unaccreted debt discount and unamortized debt issuance costs,' the operative phrase 'carried at' indicates the carrying amount disclosure, so select DebtInstrumentCarryingAmount, NOT DebtInstrumentFaceAmount. The face value is only the correct tag when the disclosure explicitly asks for the face value or principal amount without the 'carried at' framing. Always check whether the disclosure describes the carrying amount (book value) or the face value (principal).
[err-00015] helpful=0 harmful=0 :: MISTAKE: Defaulting to reportable segments when the sentence describes operating segments. When a sentence states 'The Company operates its business through two segments,' this describes operating segments, so select NumberOfOperatingSegments, NOT NumberOfReportableSegments. Only select NumberOfReportableSegments when the sentence explicitly mentions 'reportable segments' or 'reportable segment information.' The distinction: 'operates through' or 'segments' generally = operating segments; 'reportable segments' = reportable segments. Never assume reportable over operating without explicit 'reportable' language.
[err-00016] helpful=0 harmful=0 :: MISTAKE: Over-relying on the 'equity method' keyword when the sentence frames the entity as a 'related party.' When a dollar amount is described as 'fees charged to related party investments' or similar related-party framing, select RevenueFromRelatedParties, NOT IncomeLossFromEquityMethodInvestments. The 'equity method' keyword is a red herring when the sentence's explicit framing is 'related party.' Prioritize the sentence's actual semantic framing (related party) over surface-level keywords (equity method). Always check whether the entity is explicitly framed as a related party before selecting equity-method tags.
[err-00019] helpful=0 harmful=0 :: [err-00005-GRANTED-NESTED] helpful=1 harmful=0 :: MISTAKE: When an entity describes 'granted' units that are outstanding/nonvested, do NOT default to GrantsInPeriod. In this taxonomy, 'granted' units that are outstanding/nonvested map to NonvestedNumber, not GrantsInPeriod. GrantsInPeriod captures a different concept (e.g., grants in a specific period, or a different type of grant). Always check whether the 'granted' units are outstanding/nonvested (map to NonvestedNumber) or a different type of grant (map to GrantsInPeriod). The word 'granted' refers to the grant event, but the ground truth maps it to NonvestedNumber when the units are outstanding/nonvested. Never assume 'granted' = GrantsInPeriod without verifying the units' status (outstanding/nonvested vs. a different type of grant).
## PROBLEM-SOLVING HEURISTICS

[ph-00013] helpful=0 harmful=2 :: VERIFICATION CHECKLIST (apply before finalizing any tag): (1) Identify the specific entity and its semantic role in the sentence (e.g., depreciation expense, authorized share count, exercise price, cash excluded from balance). (2) Determine the data type: dollar amount -> CompensationCost/Expense tags; share count -> TotalFairValue/NumberOfShares tags; time period -> PeriodForRecognition/VestingPeriod tags. (3) Match to the MOST SPECIFIC tag capturing the core accounting concept, not a superficial keyword/value match. (4) If no exact tag exists, select the closest semantically related tag and verify the semantic relationship. (5) When multiple entities share the same numeric value, anchor each tag to its specific entity occurrence, not the value. (6) Output the tag with EXACT case from the provided list. (7) Re-read the sentence to confirm the mapping is consistent with the entity's actual role. This sequential verification prevents the superficial matching errors warned against in the existing COMMON MISTAKES bullets and ensures each tag is anchored to the correct entity.
## CONTEXT CLUES & INDICATORS

[ctx-00002] helpful=1 harmful=0 :: CONTEXT CLUE: The phrase 'unrecognized compensation cost' (or 'compensation cost not yet recognized') is a direct textual match to the tag family EmployeeServiceShareBasedCompensationNonvestedAwardsTotalCompensationCostNotYetRecognized. When this exact phrase appears, prioritize the tag that literally contains 'TotalCompensationCostNotYetRecognized' over semantically similar alternatives like 'fair value of grants'.
[ctx-00006] helpful=1 harmful=2 :: CONTEXT CLUE: When multiple entities share the same numeric value, identify each entity's semantic role from its surrounding text before selecting a tag. For example, 'exercise price of the Rights to purchase common stock' describes a class-of-warrant/right exercise price (map to ClassOfWarrantOrRightExercisePriceOfWarrantsOrRights1), while 'price per share in a private placement' describes a sale-of-stock price (map to SaleOfStockPricePerShare). Even if both values are identical (e.g., both $2.87), they map to DIFFERENT tags because they describe different entities. Anchor each tag to the specific entity occurrence it describes, not to the value.
[ctx-00008] helpful=1 harmful=0 :: CONTEXT CLUE: Distinguish between the 'term of the award' (expiration period) and the 'vesting period' (requisite service period) — these are distinct concepts that must not be conflated. The 'term of the award' is the period during which the option/award is exercisable (e.g., 'The term of any stock option awards... is ten years' = ExpirationPeriod). The 'vesting period' is the requisite service period over which the award vests (e.g., 'amortized... over the requisite service period, which is generally the vesting period' = VestingPeriod). When text mentions 'years' in the context of the award's term or exercisability, map to ExpirationPeriod, NOT VestingPeriod. Only map to VestingPeriod when the text explicitly references the service period, vesting schedule, or requisite service over which the award vests.
[ctx-00009] helpful=0 harmful=0 :: When no exact tag exists in the provided list, select the closest semantically related tag. For example, if the entities are cash/restricted-cash amounts and no dedicated cash/restricted-cash tag exists, 'CashAndCashEquivalentsFairValueDisclosure' is the best available match. Always prioritize tags that are semantically related to the entity's nature over tags that are unrelated to the entity's nature.
[ctx-00011] helpful=1 harmful=0 :: ENTITY-FIRST SEMANTIC MATCHING: Before selecting any XBRL tag, identify the specific financial entity being described in the sentence and determine its nature (e.g., cumulative effect adjustment, amortization expense, goodwill carrying amount, share count, dollar amount). This is the primary anchor for tag selection. When an exact tag match doesn't exist, select the tag that best captures the core accounting concept of the entity, prioritizing semantic similarity over superficial textual matches. For example, a cumulative-effect adjustment to retained earnings maps to 'CumulativeEffectOfNewAccountingPrincipleInPeriodOfAdoption' even if the specific context (credit losses) differs, because it captures the cumulative-effect adjustment concept. Always verify each mapping against the actual semantic role of the entity in its sentence, not against the numeric value or superficial keywords.
[ctx-00017] helpful=0 harmful=0 :: DISCLOSURE SEMANTICS OVER KEYWORD MATCHING: XBRL tags reflect the actual accounting disclosure semantics, not just surface-level keywords. For each entity, identify the core accounting concept being disclosed and match it to the tag that captures that concept, not the most obvious keyword. For debt instruments, 'carried at' = carrying amount (DebtInstrumentCarryingAmount); for segments, 'operates through' = operating segments (NumberOfOperatingSegments); for related-party fees, 'related party' framing = RevenueFromRelatedParties. The disclosure context and explicit framing of the sentence determine the correct tag, not generic data types or keyword matches. This principle applies across all tag families and prevents superficial matching errors.
## OTHERS
[misc-00003] helpful=1 harmful=2 :: DATA-TYPE-FIRST HEURISTIC: Before selecting any XBRL tag, determine the entity's data type: (1) dollar amount -> map to 'CompensationCost'/'Expense' tags; (2) share count -> map to 'TotalFairValue'/'NumberOfShares' tags; (3) time period -> map to 'PeriodForRecognition'/'VestingPeriod' tags. Never assume a dollar amount represents a 'fair value of grants' — verify the data type explicitly.
[misc-00004] helpful=0 harmful=2 :: TIME-PERIOD DISAMBIGUATION: For entities describing how long compensation cost will be recognized (e.g., '2.32 years' weighted-average recognition period), prefer the tag ending in 'PeriodForRecognition' (e.g., ...TotalCompensationCostNotYetRecognizedPeriodForRecognition1) over 'VestingPeriod' tags. 'VestingPeriod' describes the vesting schedule of awards, while 'PeriodForRecognition' describes the expense-recognition timeline — they are distinct concepts even if numerically similar.
[misc-00007] helpful=0 harmful=0 :: CASE-EXACTNESS HEURISTIC: XBRL tag names must be output with the EXACT case as specified in the ground truth, not assumed standard capitalization. The model failed by outputting 'ShareBased' (capital B) when ground truth is 'Sharebased' (lowercase b). Do NOT normalize or 'fix' the case of tag names based on convention or readability. Always copy the tag name verbatim from the ground truth or the provided tag list, preserving the exact capitalization of every word including prefixes like 'Sharebased', 'ShareBased', 'AwardVestingPeriod', etc. A case mismatch is a hard error even if the tag is semantically correct.
[misc-00018] helpful=0 harmful=0 :: GROSS-NET DEFAULTING HEURISTIC: When a tag family has both Gross and Net variants, the sentence's qualifier is the deciding factor. If the sentence says figures are 'reported net of' the concept, the figure is the NET amount (select the Net variant). If it says 'gross of' or 'before', the figure includes the concept (select the Gross variant). Do not default to Gross when 'net of' language is present. Verify the qualifier before finalizing the variant selection.
